## R2-Q01 DOM 版具体容器的 true flow 边界

### 本次实际做法

- 题内这些容器当前均是内部固定坐标。
- 外层 flow 不意味着内部已经通过 true flow 验收。
- 没有证据确认曾尝试下述转换，也没有相关失败结果。

### 通用建议

#### 1. `新书与推荐` 1:211：新增左栏，再做横向流

- 区域左右 `padding` 各 125。
- 左右栏 `gap` 20。
- 左栏宽固定 790，右栏宽固定 380。
- 交叉轴默认顶部对齐。
- 左栏内部采用纵向结构：
  - 上 `padding` 18。
  - 标题槽高 38。
  - 标题与目录 `gap` 2。
  - 目录高 496。
- 高度闭合：`18 + 38 + 2 + 496 = 554`。
- 右栏保留自身 58 高的标题区与 496 高列表。
- 不要强行对齐两边文字框的顶部；也不要在父级写了 125/20 后，再把同样的偏移重复写入子项坐标。

#### 2. 网格：优先“横向行 + 纵向列表”

- 新书：2 行，每行 5 卡。
- 在线读书：3 行，每行 7 槽。
- 固定列数属于 `faithful` 配置；不能根据一次截图臆测自动换行规则。
- 单个 Figma grid 只有在当前编辑能力、序列化和精度都验证后，才作为等价实现；先不进入默认白名单。
- 两层 stack 能在各自层内真实排列，但不会自动把卡片跨行重新分配。
- 增删后在重建时重新组行，应标记 `regroup-on-rebuild`。
- 若要求画布上编辑时原生自动换行，需要另行验证 wrap/grid。
- 不能把两层 stack 称为原生响应式网格。
- 当前 Figma 子节点顺序反向，不足以证明源 DOM 本身反向。分别保存：
  - `dom_order`
  - `figma_child_order`
  - `visual_order`
- 未知的源 DOM 顺序标未知。按视觉行列建立展示顺序，在行列表层重排，不改变内容身份；记录旧序到新序映射、矩形和行聚类依据。
- 复杂重叠、纵排或 RTL，不能直接套“上到下、左到右”。

#### 3. `新书目录` 1:243：固定 142，不用 Fill 均分

#### 4. `图书` 1:244：封面槽 + 图书信息层

#### 6. `古籍目录` 1:312：两行 flow，线条不占流

- 只说“绝对定位”不够，还要记录所属容器和锚点，否则内容增长后线条会留在原处。

#### 7. 转换顺序与扰动验收

- 先设计父级职责，再在副本由内到外实施。
- 先固定边界、建立缺失 wrapper 和顺序映射；叶子卡片、行验证后，再接入栏目。
- 允许“父 flow + 子固定”，但必须说明哪些尺寸传播被子固定阻断。
- 建议实验：
  - 左右栏高度 +40：区段高度应取两栏最大值。只有较矮栏加 40 且仍较矮时，外层不必增高 40。
  - 网格增删：按 5/7 列重新组行。`faithful` 不允许卡片自行随意折到下一行；两层 stack 的跨行组装不是原生自动换行。
  - 长标题：`faithful` 仍受两行槽约束，超出按显式截断策略处理；`adaptive` 才要求卡片和行高增长。
  - 古籍第一行实际增高 40：第二行和行分隔线按约定下移 40，列线随面板拉长。
  - 宽度 ±10%：是约束测试，不预设原站响应式行为。`faithful` 固定列宽不足时明确报告不支持，不能静默压卡片；`adaptive` 事先给出变列规则。
- 失败判据：丢项、错序、非预期遮挡、错误折行、线条脱离、关键矩形偏差超过 1 CSS px，均判失败并恢复原子树。
- 声明不支持某尺寸，不等于通过了该尺寸的响应式测试。

## R2-Q02 单子项容器与冗余 `layoutMode`

### 本次实际做法

- 沿用题内统计：43 个单在流子项容器与 44 个零在流子项裁剪容器承担不同职责。
- R1 抽查证明裁剪窗口的唯一大图为绝对定位；没有执行移除布局后的对比实验。

### 通用建议

#### 1. 分开决定“保留 Frame”和“保留 `layoutMode`”

- 一个裁剪窗口即使移除 Auto Layout，也仍应保留 Frame 与裁剪能力。
- 不能把“移除布局设置”等同于“删除容器”。

#### 2. 有布局职责的单子项保留

需要下列任一明确职责时，可保留：

- 居中、贴边等对齐。
- `padding`。
- `Hug` 内容尺寸。
- `Fill` 可替换槽位。
- 需要尺寸变化后仍维持的布局关系。

记录具体行为，不以“以后可能有用”作为唯一理由。固定 24×24 图标居中于可变按钮是正例。

#### 3. 纯裁剪、零在流子项

- 新建时默认普通 Frame。
- 已有节点列为移除 `layoutMode` 的候选。
- 移除前后需要保留并核对：容器尺寸、裁剪、图片偏移、外层占位及参与方式。
- 父级 `Hug/Fill`、最小尺寸耦合未弄清时，不立即移除。

#### 4. 子容器是 flow，不代表父也必须 flow

- 父只做坐标或裁剪边界：可以普通 Frame。
- 父需要 `padding`、对齐、宽度填充或随子项增高：需要相应布局。
- 尺寸变化只有跨越每层尺寸依赖，才能向外传播。
- 普通 Frame + 固定高度，不会自动包住变高的内层 flow。

#### 5. 未知时不做破坏性优化

- 已有稿：默认保留当前结构，标记 `unknown`。
- 新建稿：保留语义 Frame，但不凭空开启 stack；先用固定几何，等待核对。
- 未知项不自动进入 true flow。

#### 6. 决策存储

- IR 作为策略事实源，manifest 记录输出和验证结果，图层名只做人类识别。

| 字段 | 含义 |
|---|---|
| `container_key` | 容器稳定语义键 |
| `role` | 语义角色 |
| `in_flow_count` | 在流子项数 |
| `absolute_count` | 绝对子项数 |
| `layout_required` | 是否需要布局 |
| `layout_purpose` | 布局职责 |
| `sizing_dependency` | 尺寸依赖 |
| `clip_required` | 是否需要裁剪 |
| `decision` | 保留、移除候选、固定保留等 |
| `evidence` | 决策证据 |
| `confidence` | 已测、推断、未知 |
| `verification` | 验证状态 |
| `output_node_ref` | 当前输出节点引用 |

- `layout_purpose` 至少区分：`arrange / align / padding / content-sizing / clip-only`。

### 依据 / 可复现证据

建议实验：

- 按钮变宽，图标仍应居中。
- 替换大图，裁剪窗口外部占位不变。
- 内层内容增高 40，检查父高度是否按预期增长。
- 三项对应不同职责，不能用“成员 ≥2”统一判断。

### 不确定项

- 学生 V1 具体实现未审查；已有 43 个单在流子项容器并非全部验证过对齐、`padding` 和内容适应。

### 失败或放弃的方案

- 无历史删除失败记录。
- 不建议：单子项全部扁平化；裁剪容器全部开启 flow。

### 我的备注

- 节点名、节点内附属信息，都不应成为唯一策略存储。
- 当前环境不保证支持节点内写入自定义数据；2.0 应将外部可导出的 IR/manifest 作为必需项。

## R2-Q03 资产清单、裁剪来源与背景/渐变/伪元素

### 本次实际做法

- DOM 版 44 次图片使用、24 个唯一原资源，按题内证据引用。
- 此前并未完整附带下列资产契约。
- 诊断中记录了某项缺口，不代表该项已经进入重建规格。

### 通用建议

#### 1. 拆成资产、使用实例、采集状态三层

避免把原图与某次裁剪混为同一实体。

**资产层**

- `asset_id`。
- 来源类型。
- 原始 URL、最终 URL。
- 内容 hash。
- MIME。
- 原始像素宽高。
- 可用性、解码状态。
- 采集引用。
- 访问限制说明。

**使用实例层**

- `use_key`。
- 来源元素与角色。
- `asset_id`。
- 渲染内容框、边框。
- `object-fit`、`object-position`。
- 变换、透明度。
- 裁剪形状与矩形。
- 输出尺寸。
- 可替换性。
- 替换契约。

**坐标与状态层**

- `capture_id`。
- CSS 视口、DPR。
- 浏览器及画布缩放。
- 截图像素尺寸。
- 滚动偏移。
- 矩形所属坐标系。
- 加载、占位、缺失状态。
- 证据等级。

CSS 背景另记：

- `background-size`。
- `position`。
- `repeat`。
- `origin`。
- `clip`。
- 多层顺序。

不能把背景图一律套成 `object-fit`。

#### 2. 同一原资源默认去重，多次使用分别记录窗口

以下情况才优先生成独立派生裁片：

- 接收方需要脱离原图的独立资产。
- 需要局部脱敏。
- 原图巨大，只需小部分。
- 接收环境不能保留变换。

派生项仍需记录父资产 hash 和裁剪关系。独立裁片不等于独立内容身份，也不一定更省体积。

#### 3. 背景、渐变、伪元素、SVG 的优先级

**背景图**

- 原资源 + 正确背景映射优先。
- 复杂重复、混合不支持时，再做独立局部栅格化。

**CSS 渐变**

- 可准确表达时使用原生渐变，保留：层数、角度或坐标、`stop`、混合方式。
- 不能准确表达时，局部栅格化并标记。

**`::before` / `::after`**

- 先当作有样式和叠放关系的渲染对象。
- 简单装饰 → 原生形状。
- 文本 → 文本。
- 图像 → 原资源。
- 不支持的滤镜、复杂混合、边界不明 → 局部裁片。
- 伪元素不一定只是装饰，不能统一当背景处理。

**inline SVG**

- 优先保留实际矢量资源。
- 含不支持的滤镜、外链、复杂特效时，保留原始来源，并局部栅格化。

共享全页截图裁剪是最后的视觉降级，不是 DOM 默认资产策略；本轮不展开截图路线融合。

#### 4. 共享全页图裁剪的最低记录

- 源 hash 与尺寸。
- `capture_id`。
- 窗口矩形及坐标系。
- 父级裁剪或蒙版。
- 内层图尺寸。
- 完整变换。
- 偏移。
- `FILL/FIT` 策略。
- 透明度。
- 缩放、DPR。
- 叠放顺序。

只有窗口矩形和负偏移，不足以复现带旋转、缩放或复杂裁剪的情况。优先保存完整变换，避免各参数被重复应用。

#### 5. 可替换性状态

| 状态 | 含义 |
|---|---|
| `independent` | 独立资源，可按既定槽位契约替换 |
| `derived` | 独立派生图，但需保留派生契约 |
| `reference-only` | 只保证当前外观 |
| `missing` | 目标资源缺失 |

- 共享大图裁剪、不能隔离文字与背景的合成区域，默认 `reference-only`。
- 不得因此宣称素材内部可编辑。
- 原生重建对象可以另记 `primitive` 和编辑能力，不硬塞入图片枚举。

#### 6. 失败策略由采集目标决定

**`faithful-as-captured`**

- 保留指定状态里真实存在的占位，同时记录：期望资源、实际占位资源、占位原因是否已知。

**`stable-loaded`**

- 先有限重试触发加载和解码；仍缺图时返回 `partial/missing`，不能宣称完整成功。

只有在以下两个条件都满足时，才使用局部裁片，并记录 `mode_change`：

- 获准视觉降级。
- 同状态截图确实包含目标内容。

截图里也是占位，就不能“恢复”不存在的原图。

### 依据 / 可复现证据

- 唯一图片数与引用次数不同，说明资产身份和使用次数需要分开。
- R1 的负偏移裁剪案例说明，只有 `imageHash` 不能复现裁剪。

建议实验：

- 一张原图在两处使用不同 `object-position`。替换源图后，各自槽位保持、各自映射保持，不丢失另一使用实例的独立配置。

### 不确定项

- 复杂 SVG、CSS 混合、背景多层、伪元素在学生当前实现中的支持范围未知。
- 无性能数字和准确率结论。

### 失败或放弃的方案

- 无已验证历史失败。
- 不采用：`decode` 成功就等于原图加载成功；所有缺图都拿其他时刻截图补齐；有 hash 就等于可独立替换。

### 我的备注

- 未知字段保留 `unknown` 并说明来源，不填默认值伪装测量。
- 截图裁片只有可追溯、状态匹配时，才能作为本轮显式降级项。

## R2-Q04 重复卡片/同名栏目的命名与稳定语义键

### 本次实际做法

- 三版有同名节点。
- 此前没有建立可核实的跨重建语义键体系，不能将当前 ID 或名称当作稳定身份。

### 通用建议

#### 1. 分开展示名称、实体身份、出现身份、槽位身份

建议命名模板：

```text
在线读书 / 第01行
→ 图书卡片 / 王尽美文集 / 显示01

推荐新书 / 第01行
→ 图书卡片 / 生命天书 / 显示05

图书推荐 / 显示01
→ 排行条目 / 复仇游戏
```

- 这些是概念模板，不是新建图层。
- 序号仅提示当前排序，不进入稳定实体键。

#### 2. 稳定键组成

- `entity_key`：站点命名空间 + 经验证的内容类型、业务 ID。
- `occurrence_key`：页面或栏目语义键 + 来源稳定条目 ID，并关联 `entity_key`。
- 书籍 ID 可以从经过验证的详情地址提取，但不能假定所有数字都是内容 ID，也不能随意删除 URL 中影响身份的参数。

#### 3. 重复和变化

- 同书不同栏目：`entity` 相同，`occurrence` 不同。
- 同书同栏目重复：优先来源条目 ID 或稳定槽位键。没有时，用父级语义路径、锚点和邻域作为候选匹配；无法消歧则标 `ambiguous`。
- 书名变化、业务 ID 不变：实体键不变。
- 只有标题、DOM 路径、序号：没有可靠稳定保证；标 `weak/unknown`，不强配。

#### 4. 定位证据不是身份

以下只作为定位或辅助证据：

- `source_locator`。
- 选择器、DOM 路径。
- `visual_index`。
- 行列坐标。

DOM 改版、插项、换序都可能使它们失效。标题 hash 随标题变化，宜作辅助指纹，不宜作主键。冲突必须报告，不允许后写覆盖前项。

#### 5. 存储建议

- IR：身份与证据。
- sidecar manifest：输入键 → 输出节点、版本映射。
- 图层名：可读展示。
- 节点内附属信息：有受支持能力时可作便捷副本，不是必需或唯一真值。

节点内信息可能被删除、复制或跨版本失效。外部清单便于比对，但必须带 `schema_version`、`capture_id`、输出版本，避免清单与当前稿脱节。

#### 6. 动态内容

- 使用 `slot_key + 当前 entity_key`。
- 例如：主广告槽身份稳定，当前广告内容可变；轮播角色和当前素材分开记录。
- 来源没有稳定槽位时，标 `dynamic/weak-match`，不承诺追踪同一内容。
- 位置键能追踪位置，不能冒充内容键。

#### 7. 禁止作为最终唯一识别依据的名称

- `内容`。
- `图书位置`。
- `Frame 123`。
- `矩形`。
- 重复且无父级、内容区分的 `图书`、`栏目标题`。

这些名称可以作为角色名存在，但必须有父级与稳定映射。不是禁止全树出现重复名称。

### 依据 / 可复现证据

- 题内重复名已足以证明 `name` 不唯一。

建议实验：

- 列表头部插一本书。
- 同一本书改标题。
- 同书出现在两个栏目。
- 广告更换素材。

预期：原实体按 ID 保持对应；出现位置与槽位变化分别报告；模糊匹配不得报告为确定命中。

### 不确定项

- 源页面是否提供稳定条目 ID。
- 重复项能否消歧。
- 跨栏目移动是否保留出现身份。最后一项需要产品定义：实体身份可以保持，出现身份未必保持。

### 失败或放弃的方案

- 无历史键策略实验。
- 不建议以下项单独成为全局永久主键：标题 + 序号；完整 DOM 路径；Figma 节点 ID。

### 我的备注

- `identity_status` 建议区分：`verified-id / scoped-slot / weak-match / ambiguous / unknown`。
- 不为未经校准的匹配结果编造置信概率。

## R2-Q05 DOM 采集的参考状态契约

### 本次实际做法

- 学生陈述已有三态与会话降级，本轮未独立审查。
- 本次 DOM 采集记录了 1440 视口宽、截图、部分矩形、样式和资源，但未形成下列完整状态契约。
- 不能补称以下事项都已验证：字体实际回退、原图全部加载、DOM 与截图严格同步。

### 通用建议

#### 1. 采集契约最低状态字段

- 目标 URL、最终 URL、重定向。
- 目标页面类型。
- 采集 `profile`。
- CSS 视口。
- DPR。
- 设备与浏览器缩放。
- 截图范围、像素尺寸。
- 滚动位置。
- 浏览器版本。
- 语言、时区、色彩和字体环境。
- 是否存在授权会话。
- cookie 同意条、模态框状态。
- 轮播目标帧。
- 动画、过渡控制方式。
- 字体加载及实际使用证据。
- 图片、背景的加载与解码状态。
- `sticky/fixed` 策略。

全页截图特别说明：

- 必须记录是分块拼接、扩展视口，还是其他全页捕获方式。
- 滚动触发懒加载后，应返回目标滚动位置，再等待稳定。
- 不同 full-page 实现可能影响 `sticky` 位置、视口单位、懒加载和截图拼接结果。

“冻结”不仅是主动固定，也包括无法固定时记录并拒收不稳定状态。关闭动画也可能改变外观，不应当作默认正确状态；需记录控制方式和目标帧。

#### 2. 同态验证：M0 → S → M1

稳定后：

1. 测量 `M0`。
2. 截图 `S`。
3. 再测量 `M1`。

不宣称这是原子同步。三者记录共同 `capture_id`，以及：

- 时间。
- 关键矩形。
- 文本摘要。
- 可见状态。
- 实际图源、hash、自然尺寸。
- 字体状态。
- 轮播标记。
- 滚动值。

起始判据：

- 关键矩形前后变化 ≤0.5 CSS px。
- 资源与目标状态一致。
- 再判 `stable`；0.5 需用样例标定。

`layout hash` 仅作快速筛查，必须附：字段列表、坐标系、量化精度、`schema`。hash 相同不证明所有像素相同。截图前后也可能发生短暂变化再恢复，需结合目标区域的视觉证据。

#### 3. 不可用与部分可用

以下情况应重试或拒收：

- 持续布局抖动。
- 字体在 `M0/M1` 间变化。
- 轮播切换。
- 目标内容被遮挡。
- 实际图源变化。
- `sticky` 策略不明确。
- DOM 与截图显著不一致。

`stable-loaded` 目标下，仍有目标缺图，不能完整成功。`faithful-as-captured` 若指定的就是占位或登录页外观，可以忠实采集该状态，但不能将它当作目标内容页成功。

#### 4. 三态不能只看关键词

**`hard_login`**

- 预期内容缺失。
- 主导登录或密码表单。
- 认证 URL。
- 认证状态。
- 正文里的“登录”链接不是登录障碍证据。

**`soft_block`**

- 挑战、验证码、限流。
- 访问拒绝特征。
- 正文缺失。
- 异常跳转。
- HTTP 状态。
- 200 可能是挑战页，403 也不能单独解释页面类型。

最可靠的是：页面特定内容锚点 + 表单/挑战特征 + URL/状态的多信号联合。信号冲突时，标 `unknown/blocked`，停止自动判成功。登录表单和正文同时存在可能只是浮层，需要检查遮挡和访问范围。

不自动填写凭据或绕过验证码，不把访问升级重试当成本轮状态修复。

#### 5. 重试预算

建议起点：

- 首次采集 + 最多 2 次有理由的修复，共 3 次。
- 单次 60 秒。
- 总预算 180 秒。
- 页面可另行配置。

分段滚动还应有最大步数、时限，避免无限列表。每次必须有可行动原因，例如：

- 尚未触发懒加载。
- 图片正在解码。
- 过渡尚未结束。
- 需要重新测量。

记录每次改变了什么。明确登录、授权障碍不盲重试。超过预算，返回 `partial/failed` 及缺口清单。真实会话有正文，不代表截图完整；也不能直接把 DOM 失败改成 `screenshot_only` 成功。

#### 6. 每次尝试最低记录

- `attempt_id`。
- 父 `attempt`。
- `capture_id`。
- 开始、结束时间。
- 模式和原因。
- URL、页面类型。
- 视口、DPR、缩放、滚动。
- 脱敏会话环境标识。
- 动作与等待条件。
- 前后状态摘要。
- 字体与图片清单。
- 关键矩形及摘要。
- 截图引用与 hash。
- 分类信号。
- 预算使用。
- 结果。
- 失败码。
- 缺口。
- 下一步或停止原因。

不得保存：密码、cookie 值、访问令牌等会话秘密；带凭据的 URL、查询参数应脱敏。

### 依据 / 可复现证据

R1 中的懒加载、轮播和字体不确定性说明，单次访问、`networkidle` 都不足以定义参考状态。

建议实验：分别延迟字体、延迟封面、切换轮播、改变 sticky 滚动状态，检查契约是否拒收或明确标 `partial`，而不是只判断页面存在文字。

### 不确定项

- 未审查 V1 三态分类准确率、真实会话能力、现有尝试字段、full-page 具体行为。
- 合理超时分布和阈值需学生实验标定。

### 失败或放弃的方案

不将以下任何单一信号当作充分成功条件：

- 等待固定秒数。
- 仅 HTTP 200。
- 仅关键词命中。
- 单一 layout hash。
- 看到正文。

本轮未执行新会话降级或路线融合。

### 我的备注

- 建议结果明确区分：`complete / partial / rejected`，并记录参考 `profile`。
- 状态契约应允许诚实失败，不能通过降低目标且不报告来提高成功率。

## R2-Q06 中文文本度量、行高与字体回退

### 本次实际做法

- 按题内统计，DOM 版保留多种像素行高，不是统一 140%。
- 但这只证明属性设置不同，不能证明字体、基线和换行已逐项验收。
- 未写 `textAutoResize` 的 28 项，不能直接认定为某种模式，应核对运行时或序列化默认值。
- 学生 V1 对缺失行高使用 1.4em 的描述，作为输入事实引用。
- 此前没有完整的浏览器逐字体 run 与 Figma 渲染对照记录。

### 通用建议

#### 1. 文本字段分来源与输出

**内容和身份**

- `text_key`。
- 内容及 hash。
- 语言。
- 方向、`writing-mode`。
- 来源角色。
- DOM 定位。
- 原始文本到可见文本的映射。

**字体**

- 声明 `font-family`。
- 实际字体 run 及证据。
- 字体可用性。
- 字号。
- 字重。
- 字形样式。
- 可变轴。
- 是否合成粗体、斜体。
- 字距、词距。

**行高与排版**

- `line-height` 原始声明。
- computed 值。
- used 值。
- 容器 `content-box`。
- `padding`。
- 可用宽度。
- `white-space`。
- 换行、断词规则。
- `text-transform`。
- 对齐、缩进。
- `overflow`、`clip`。
- `ellipsis`、`line-clamp`。
- 最大行数。

**实测布局**

- 每行文本范围、矩形。
- 行数。
- 文字框边界。
- 字形可见边界。
- 基线、度量的来源与可用性。

**Figma 输出**

- 实际字体。
- 字号、字距、行高。
- 文本框宽高。
- `auto-resize`。
- 换行。
- 可见结果。

不能用同一字段覆盖浏览器目标值和 Figma 实际值。`resolved_font` 应支持逐 run，因为中文、拉丁、数字和符号可能由不同字体提供字形。`computed font-family`、字体加载完成、字体可用检查，都不能单独证明实际字形来自哪个字体；拿不到实际 run 就标 `unknown`。

#### 2. `normal` 保留 `normal`，测量与估算分开

- 优先记录实际布局结果，同时保存字体度量推算值和方法，用于对照。
- 相邻行位置差可以估计行进距离。
- Range 矩形不一定等于 CSS 行盒。
- Range 矩形不等于字形基线。
- 多字体、内联元素会进一步改变高度。
- 单行 `normal` 没有相邻行，不能凭一次文本框高度推断精确行高。
- 1.4em 只可作为显式 low-fidelity 回退。
- 必须记录：`estimated`、方法、理由、待验收。
- 不能命名为 `measured`，也不能据此通过精确复刻验收。
- 不能因为数值相近，就把 `normal` 改写成确定 px。

#### 3. 四项独立验收

| 项目 | 起始判据 |
|---|---|
| 文字框边界 | 关键边界偏差 ≤1 CSS px |
| 基线 | 有可靠证据时，目标偏差 ≤0.5 CSS px |
| 换行 | 未改内容、宽度时，行数和换行点一致 |
| 可见字形 | 可见边缘偏移 ≤1 CSS px 作为几何检查起点，另核对字形特征 |

截图、画布缩放需要换算。拿不到基线时，标 `unknown/not-evaluated`，不能填 0 误差。抗锯齿、hinting 和色彩会影响像素差；跨渲染器不设置未经标定的统一像素通过率。字体相同也不保证逐像素相同。字形检查还应覆盖标点、粗细、缺字、省略号，不能只看文本框。

#### 4. 原字体不可用：先报告，再降级

保留：

- `source_declared_font`。
- `output_font`。
- `fallback_reason`。
- 受影响范围。
- 验收状态。

`faithful` 要求高时，先请求可用字体或明确接受误差。获准替换后，用真实替代字体重新排版，不能仍声称使用原字体。仅保留不存在的字体名称、掩盖实际显示，是最容易误导的做法。

不优先通过改字号、字距来强行凑宽，因为可能修好一行、破坏其他行，改变字号语义，破坏标点节奏。必要微调要保留：原值、改值、原因、逐角色验证、回退方式。不静默全页统一缩放。

#### 5. 中文优先验证三项

1. **实际字形字体与字重**：中西文混排、数字、缺字、合成粗体。
2. **可用宽度与逐行换行点**：全角标点、中文禁则、省略号、字距。
3. **行进距离、基线与槽位**：固定两行槽、`Hug`、截断、内容高度传播。

三项稳定后，再处理微小光学偏移。

#### 6. 最小证据字段集

- `content`。
- `source_rect`。
- `available_width`。
- `font_declared`。
- `font_resolved_runs`。
- `font_size`、`font_weight`。
- `line_height_declared`。
- `line_height_computed`。
- `line_height_used`。
- `line_ranges`、`line_rects`。
- `baseline`。
- `overflow_policy`。
- `output_font`、`output_layout`。
- `comparison`。

每个值附：`status`、来源、方法、`capture_id`、单位。

| 状态 | 含义 |
|---|---|
| `observed` | 已观察、已测或已读取 |
| `derived` | 由已知证据推导 |
| `estimated` | 估算 |
| `unknown` | 未知 |

`derived`、`estimated` 汇总时可以归为“推断”，不能混进“已测”。

必须实测后才能宣称精度的项：

- 源与输出实际几何。
- 行数、换行点。
- 输出字体的实际可用与排版。
- 声称基线对齐时所需的可靠基线证据。

缺失 CSS 规则可以推断，`normal` 可以估算，但必须保留不确定性。混合样式按 run 保存，不压成一个角色默认值。

### 依据 / 可复现证据

- 16px 字号、22px 行高对应的两行标题槽 44 高，是槽位高度证据，不是基线 151.28 的证据。
- 作者 y=202.96 与标题槽底部的间距，也不是字体 ascender、descender。

建议实验：

- 同一中文标题分别使用：原字体、替代字体；固定 44 槽、`Hug`；原宽、窄 10%。
- 分别比较文本盒、基线、换行、字形。
- 同时加入中英数字、全角标点、省略号，不能只测纯中文短标题。

### 不确定项

- 原浏览器逐 run 字体。
- `normal` 实际 used 行盒。
- 可靠基线提取方式。
- 跨渲染器字形阈值。
- 学生当前字体测量能力。
- 本次无法确认。

### 失败或放弃的方案

- 无已验证的历史替字体实验。
- 不建议：用 140% 统一覆盖；把 Range 顶部当基线；把声明字体当实际字体；文本盒通过就宣布文字 1:1。

### 我的备注

- 角色规范用于复用，不能覆盖逐元素原始证据。
- 文本框正确、换行正确、基线正确、字形正确，是四个独立结论。
- 未测项必须保留空态，不能默认通过。
