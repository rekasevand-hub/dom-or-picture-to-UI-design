# R5 Gate Matrix

> Frozen: 2026-10-22; updated: 2026-10-27
> Scope: one inventory row for every P5 or production blocker used by the
> R5-P5 roadmap. A row records where a claim may be made, not whether the claim
> has already passed.

## Verification Vocabulary

| Term | Meaning | Required evidence |
|---|---|---|
| `current-scope` | Implemented or exercised only inside the authored, deterministic or otherwise explicitly bounded current scope. | Scope statement, commands, report and limitations. |
| `pilot-verified` | Short prose form for a bounded P5 result. A durable artifact must use the scoped form below. | Frozen pilot profile, operator, thresholds, evidence hash and rollback record. |
| `verified-for:<scope>` | Evidence-backed claim for one named action, environment, build and threshold set. It is never a project-wide boolean. | Code revision, plugin build, Chromium build, Figma document, claim scope, thresholds and evidence hash. |
| `production-admitted` | A later policy decision for an explicitly declared production scope. | P5 exit evidence, production verification, residual-risk disposition and signed admission review. |

Execution states such as `not-started`, `blocked` and `conditional` do not
promote a claim. Conditional work blocks a product promise only when that
promise enters the declared release scope.

## Gate Rules

1. A P5 row may advance to `pilot-verified` only through a scoped claim with a
   frozen manifest and evidence hash.
2. A production row remains non-admissible while its residual risk lacks an
   owner, mitigation, rollback, evidence and expiry or resolution record.
3. A conditional row becomes blocking only when the corresponding promise is
   added to the release scope.
4. Project-wide boolean verification is forbidden. Every successful claim must
   remain bounded by the scope named in its row.
5. The P5 pilot result never promotes a production row to
   `production-admitted`.
