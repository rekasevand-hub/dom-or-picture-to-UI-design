# 参考侧墨迹归属：探针结果 — 2026-11-13

> 一句话：**能切准（真值 Δ1px），能解掉 59% 的不可测，且不会乱改已经量得对的 owner；
> 但换成这把尺子，几何通过数会从 478 掉到 460 —— 掉的主要是原来被裁出来的假通过。**

探针：`scripts/ink_ownership_probe.py`（只读，不连 Figma，不改门禁）。
明细：`output/_ink_ownership/probe.json`。

## 1. 做法

四条失败的修法（padding / 并集 / `box_pad=0` / 清兄弟框）都只改了窗口，没改「哪块墨属于谁」。
本探针换顺序：**先放大窗口拿候选，再按归属选**。

```
window(变体) → contrast mask → 列投影 → 1D 连通 run（按 em 比例断）
             → 取「至少一半宽度落在节点框里」的 run 并合并 → 该 run 的墨迹框
```

节点框是我们自己发射的位置，是最可靠的先验：框内的墨多半属于这条文本，框外一整段
（图标、箭头、邻居标签）不属于。多词串会拆成多个 run，但它们都在框内，合并后就是整串——
所以同一条规则同时解决「切错」和「吞邻居」。

## 2. 四个变体

| 变体 | 窗口 | 选择规则 |
|---|---|---|
| W0 | 节点框 + 4px | 无（现状，必须逐位复现门禁） |
| W1 | 节点框 + 4px | 取重叠最大的 run |
| W2 | `union(source_bbox, 节点框)` + 4px | 取重叠最大的 run |
| W4 | 同 W2 | **保留 ≥50% 落在框内的 run 并合并** |
| W5 | 同 W2 | 同 W4，且**按 `script` 分断字阈值**（CJK 0.35em / 拉丁 1.0em） |

## 4. 两个坑（都已定位并修正）

1. **「取重叠最大的 run」会把多词串切成一段**：`CONTENT SECURITY` 被切成 108 + 109，
   `© 2026 内容安全协议 v4.2` 被切成 147。W2 的漂亮数字有一半是这么来的。
   → 改成「保留 ≥50% 在框内的 run 并合并」。
2. **拉丁词间距 0.72em 会被 CJK 阈值切断**：`CONTENT SECURITY` 的真空是 229 宽，
   词间 13px / em18 = 0.72em。→ 按 `data` 里现成的 `script` 字段分阈值（W5）。

## 5. 结论

- **能切准**：三个已知样例全部命中，且 211 条原本干净的 owner 宽度漂移 **90 分位 0px**。
- **能解掉 59% 的不可测**：108 → 44。
- **但分数会掉**：几何两维 478 → 460（−18）。拆开看，**掉的这 18 条里 11 条原本是贴边 owner 的
  size 通过**——参考被裁到框宽才“过”的假通过；另有 9 条 size、8 条 position 来自参考真实变宽
  （如 `请输入0~...` 的省略号归位后参考宽 102→109）。

也就是说：**这不是一把能提分的尺子，是一把先把假通过退掉的尺子。** 换它 =
先承认此前的 95 分里有水分，再在新水位上重新调。

## 6. 接进测量前必须一起改的两件事

1. **渲染侧要不要同样走归属选择**：实测只改参考侧（W6）更差（237/210），因为两侧口径不一致；
   对称（W5）是目前最好的，但对称也会把「我们自己的文字溢出节点框」裁掉——这是它仍丢 9 条
   size 的原因之一。
2. **`box_pad` 在 W5 里只影响窗口边缘**，不再是 8px 的宽度红利；换尺子之后
   `letterSpacing` / 字号伺服的幅度才第一次可信。

## 7. 不做

- 不再在 5 族上调 `min_inside` / 阈值凑分——那是拿 5 张考卷过拟合。
  上面两个修正（合并规则、script 分档）都由**真值样例**驱动，不是由总分驱动。

## 8. 已接进测量（2026-11-13 15:50）
