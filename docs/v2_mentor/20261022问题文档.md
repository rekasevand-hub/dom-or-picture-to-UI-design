# 20261022 问题文档

本文件记录执行 R5-P5 路线图时暂时无法仅靠代码仓库闭环、需要导师或环境所有者确认的问题。未确认问题不会阻塞当前范围代码，但会阻塞对应的真实环境 `verified-for` 或生产准入声明。

## Q1. Task 6 的固定 Figma 试点文档

- 需要：固定 pilot 文档 URL/file key、保存版本、允许修改的页面与 root node。
- 原因：view-only、permission denied、user takeover 和两个 collaborator 的竞态必须在同一固定文档上执行。
- 当前处置：分类、manual-review policy 和 deterministic probe 已实现；真实环境状态标记为待执行。

## Q2. Task 6 的协作者与权限矩阵

- 需要：一个 view-only 账号、一个可写账号、第二个协作者账号及各自可执行/不可执行的操作。
- 原因：无法从单账号或 mock 结果推断真实 permission、rate-limit 与 takeover 行为。
- 当前处置：真实 actor/revision 继续为 `unknown`，不根据相同当前状态推断提交归属。

## Q3. Task 6 的操作员与复核通道

- 需要：operator 身份、复核入口、unknown write 的批准/拒绝记录方式。
- 原因：manual reconciliation 不能由代码自动升级为 committed。
- 当前处置：所有 unknown/partial/deletion 场景都保持 `manual-review` 和 no-resend。

## Q4. Figma Rate Limit 的可控触发条件

- 需要：允许的测试文档、可接受的限流触发方式及观察窗口。
- 原因：不能在生产工作文档上主动制造限流。
- 当前处置：分类逻辑已覆盖 429/retryAfterMs，真实触发仍待执行。

## Q5. Task 7 的真实接管与并发删除场景

- 需要：允许第二个协作者在发送后修改或删除 owned node 的明确时段。
- 原因：expected-state compensation 与 actor attribution 必须基于真实并发行为。
- 当前处置：保留 owned node evidence 与 manual-review 路径，不自动重发。

## Q6. Task 12 云主机与长时 soak

- 需要：用户云 Windows 主机、Figma Desktop 登录态、固定 plugin build、监督进程和 1h/24h/7d 排期。
- 原因：路线图明确禁止在本机启动 24h/7d soak。
- 当前处置：仅保留计划和门槛，不产生长时稳定性声明。

- 当前处置：`output/_p5_dry_run_round1/result.json` 记录 deterministic pass，但 `staged_rehearsal=not-run`，P5 保持 `blocked-environment`。
