## Q9. `max_writes=1000` 与一小时 four-writer/no-sleep 的定义冲突

- 证据：`output/_p5_dry_run_round1/result.json` 的冻结 profile 写有 `max_writes=1000`，runbook 也将 1000 写作为 abort threshold；但真实一小时 run 在四个 writer、无 client sleep 下，round 2 完成 17,395 次写，修复后的 round 3 完成 56,973 次写。
- 歧义：`max_writes` 是总写入上限、同时在途上限，还是只用于 deterministic run 的安全上限。若它是总写入上限，一小时 stress profile 必须在约 0.28 writes/s 处主动限速，这与“four writers, no client sleep”冲突。
- 当前处置：不把 `max_writes` 事后改成 17,395、56,973 或更大的数值，也不删除失败样本。两轮一小时 session 可用于吞吐、bounded journal、reconnect 和 cleanup 观察，但在导师确认阈值语义前不能据此声明完整 `pilot-verified-for`。
