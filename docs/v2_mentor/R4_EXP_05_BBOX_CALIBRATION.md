# R4-EXP-05 · 跨 DPR、缩放与字体的 bbox 容差标定

> 状态：`completed-for-current-scope`（2026-10-18），不是 `verified`。  
> 范围：1 个受控页面、4 个 DPR × 5 个 CSS 缩放 × 10 个元素，共 20 次真实截图与 200 个 bbox 样本。  
> 证据：`output/_r4_experiments/r4_bbox_calibration.json`、`output/_r4_experiments/r4_bbox_artifacts/`，以及 `r4_bbox_heatmap.png`、`r4_bbox_distribution.png`、`r4_bbox_overlay.png`。  
> 边界：截图框由作者给定的纯色背景连通域恢复，是渲染/量化口径，不是 OCR/CV 检测器基准；未修改 `src/`、`figma_bridge/`，未执行 Figma 写入。

## 1. 目的与边界

本实验回答 `R4-O03`：在 `R4-EXP-01` 写定的 `2.0 px` 绝对 bbox 容差下，不同 DPR、页面缩放和字体是否仍能在该门限内完成 DOM 与截图几何对齐，以及误差分布是否出现长尾。

实验验证的是**同一渲染结果在整数像素栅格化后的量化误差**。它不验证：

- OCR/CV 能否找到正确框；
- 旋转、变换、裁剪、遮挡、半透明、阴影或图片资产下的边界；
- Firefox、Safari、移动端或真实站点；
- `2.0 px` 是否可推广为生产通用阈值。

## 3. 测量方法

### 3.1 DOM 框

每个样本通过 `getBoundingClientRect()` 读取 `left / top / right / bottom`，单位是该缩放状态下的 CSS px。

### 3.2 截图框

每个样本使用唯一的纯色背景，文字设为透明，以避免字形抗锯齿混入颜色分割。截图以无损 PNG 捕获后：

1. 以 `min(R,G,B) < 255` 提取非白像素；
2. 对非白像素做 8 邻域连通域标记；
3. 用样本调色板把每个连通域映射回唯一元素；
4. 取连通域的物理像素外接框，再除以 DPR 转为 CSS px。

该口径包含抗锯齿边缘，是“可见背景足迹”的稳定上界；它不是 OCR/CV 检测流程。

### 3.3 比较规则

沿用 `R4-EXP-01`：

```text
max(|shot.left   - dom.left|,
    |shot.top    - dom.top|,
    |shot.right  - dom.right|,
    |shot.bottom - dom.bottom|) <= 2.0 px
```

超差只允许 `external-conflict`，不得平均两侧框。

## 4. 样本矩阵

### 4.1 字体与大尺寸样本

| profile | 字体 | 字号 / 行高 | 固有尺寸 | 固定尺寸 |
|---|---|---:|---|---|
| `arial-16` | Arial | 16 px / 1.25 | 文本决定宽高 | 240.5×38.25 |
| `times-24` | Times New Roman | 24 px / 1.10 | 文本决定宽高 | 300.5×52.5 |
| `yahei-18` | Microsoft YaHei | 18 px / 1.40 | 文本决定宽高 | 260.75×46.75 |
| `consolas-15` | Consolas | 15 px / 1.60 | 文本决定宽高 | 220.5×41.5 |

字体文件在本机均存在：`arial.ttf / times.ttf / msyh.ttc / consola.ttf`。固有尺寸样本让字体度量、行高、字距和分数像素宽度真实进入 bbox；固定尺寸样本隔离布局盒与缩放量化。

### 4.2 小尺寸压力样本

- `micro-badge`：Arial 8 px、`line-height: 1`、`1.5 px / 2.25 px` padding 的 `99+` 徽标。
- `hairline`：400.5×1.25 CSS px 的实色细线。

这两个样本用于检查小于常规 UI 元素的边界，不用于宣称文本识别或真实细线检测能力。

## 5. 结果

### 5.1 总体分布

| 指标 | 值 |
|---|---:|
| 样本 | 200 |
| 通过 `<= 2.0 px` | 200 / 200 |
| 常规字体样本 | 160 / 160 |
| 小尺寸压力样本 | 40 / 40 |
| 中位数 | 0.5000 px |
| P90 | 0.7083 px |
| P95 | 0.8333 px |
| P99 | 1.0375 px |
| 最大值 | 1.1000 px |
| 最小容差余量 | 0.9000 px |

在本次矩阵中，`2.0 px` 没有被触发失败，最坏样本仍保留 0.9 px 余量。

### 5.2 按 DPR

| DPR | 样本 | 最大误差 | 通过 |
|---:|---:|---:|---:|
| 1.0 | 50 | 0.5000 px | 50 / 50 |
| 1.25 | 50 | 1.1000 px | 50 / 50 |
| 1.5 | 50 | 0.8333 px | 50 / 50 |
| 2.0 | 50 | 0.5000 px | 50 / 50 |

最坏点出现在 DPR 1.25，而不是最高 DPR 2.0；误差没有随 DPR 单调增加。

### 5.3 按缩放

| CSS zoom | 样本 | 最大误差 | 通过 |
|---:|---:|---:|---:|
| 0.5 | 40 | 0.8333 px | 40 / 40 |
| 0.75 | 40 | 0.7875 px | 40 / 40 |
| 1.0 | 40 | 1.1000 px | 40 / 40 |
| 1.25 | 40 | 1.0375 px | 40 / 40 |
| 1.5 | 40 | 0.8333 px | 40 / 40 |

缩放 0.5 没有出现最大误差；在该口径下，连通域包含抗锯齿边缘，低缩放并未放大成超过 2 px 的边界偏差。

### 5.4 按变体

| 变体 | 样本 | P50 | P95 | 最大 | 通过 |
|---|---:|---:|---:|---:|---:|
| 固有尺寸 | 80 | 0.5000 | 0.7779 | 1.1000 | 80 / 80 |
| 固定尺寸 | 80 | 0.5000 | 0.8333 | 1.0375 | 80 / 80 |
| 微型徽标 | 20 | 0.5000 | 0.8342 | 0.8500 | 20 / 20 |
| 1.25 px 细线 | 20 | 0.5000 | 0.8435 | 1.0375 | 20 / 20 |

最坏单样本为 `dpr1p25_zoom1000 / arial-16-intrinsic`：DOM 底边 108.5，截图底边 109.6，最大边差 1.1 px。

### 5.5 位移敏感度诊断

对已测截图框整体做正向平移，再套用同一门限：

| 正向平移 | 被拒绝 | 仍接受 |
|---:|---:|---:|
| 0 px | 0 | 200 |
| +1 px | 3 | 197 |
| +2 px | 187 | 13 |
| +2.5 px | 200 | 0 |
| +3 px | 200 | 0 |
| +4 px | 200 | 0 |

该诊断说明 `2.0 px` 是带测量噪声的阈值，不表示在正向偏差方向上仍有完整的 2 px 安全余量；+2.5 px 及以上在本次样本中全部被拒绝。它不是缺陷检测准确率。

## 7. 可以写入 2.0 规格的结论

1. 在“Chromium + 纯色背景 + 连通域可见足迹”的受控矩阵内，`2.0 px` 对 200/200 个样本成立；P95 为 0.8333 px，最大为 1.1000 px。
2. 误差没有随 DPR 或 CSS zoom 单调增长；最坏点来自 DPR 1.25 / zoom 1.0，而不是边界极值。
3. 固有尺寸、固定尺寸、8 px 微型徽标和 1.25 px 细线在本矩阵内均未超过 `2.0 px`。
4. bbox 仍应只使用绝对容差并禁止平均；本实验没有提供任何“取平均更稳定”的证据。
5. `2.0 px` 可以继续作为 R4 实验合同值使用，但必须先通过状态门和配对门；几何容差不替代身份与状态判断。

## 8. 仍不能写入规格

- 不能宣称 `2.0 px` 是跨浏览器、跨平台或跨字体的通用阈值。
- 不能把纯色连通域结果写成 OCR/CV 框检测精度；仍缺真实检测器、检测框偏移、漏检和误检分布。
- 不能覆盖旋转、仿射变换、裁剪、遮挡、半透明、阴影、边框、渐变或图片资产。
- 不能把 CSS `zoom` 写成浏览器 UI 缩放或 pinch zoom 的等价验证。
- 不能把 1.25 px 细线的通过写成对所有亚像素线、图标和极小元素都成立。
- 不能把 +2 px 位移仍接受 13/200 写成容差过宽或过窄；该诊断只反映当前噪声方向与门限的交互。
