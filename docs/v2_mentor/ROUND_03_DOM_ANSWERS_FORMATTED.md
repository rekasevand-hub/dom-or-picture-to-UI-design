## R3-D01 在线目录完整尺寸与源 DOM 顺序

### 本次实际做法

- 已知目录为 1190×733、21 个槽位、7 列×3 行，以及部分位置参数。
- 源 DOM 顺序未知。
- 反向的是已经解析到的 Figma 子项顺序，不能将它写成已证实的 DOM 反向。

### 通用做法与 2.0 建议

#### 1. 区分结构提议与可执行候选

- 信息不足时，可以先记录 `proposal / pending-evidence`。
- 只有槽位、容器边界、间距、顺序策略和证据足以生成完整布局时，才进入可执行的 `candidate`。
- 不必要求每个字段都是直接测量，但推导必须列出前提、可以验算。
- 冲突或缺口尚未解决时，不得自动应用。

#### 2. 条件推导，但不能冒充新增实测

若 7 列等距、列间隙确为 10：

- 列步长：`(1008 − 36) ÷ 6 = 162`。
- 槽宽：`162 − 10 = 152`。

若行步长 237、行隙 0，且槽位等高：

- 槽高：`237`。

由此推导 padding，上／右／下／左：

- `21 / 30 / 1 / 36`。

验算：

- 宽：`36 + 7×152 + 6×10 + 30 = 1190`。
- 高：`21 + 3×237 + 1 = 733`。

这些是带前提的推导值，不是新增实测值。需要补核实全部槽位的矩形和类型，不能仅凭首末点就确认整张网格。

#### 3. DOM 顺序未知，就保持未知

建议分别记录：

- `dom_order=unknown`。
- `display_order`。
- `order_basis=visual-clustering`。
- 原 Figma 子项顺序。
- 候选行列。
- 旧序到新序映射。

视觉顺序可以作为本次展示顺序，但不能冒充 DOM 顺序。

#### 4. 网格聚类采用多种几何证据

规则网格优先结合：

- 槽位矩形的垂直重叠。
- 上沿位置。
- 水平步长。
- 内容角色。

中心点仅作辅助，不能以封面中心代表整个卡片中心。

不同高卡片、瀑布流、叠放、RTL 需要另行分型。

记录字段：

- 每槽矩形。
- 聚类容差。
- 行列号。
- 离群项。
- 人工修订。
- 规则版本。

人工锚点可以消歧，但不能隐式覆盖观测。

#### 5. 共享语义，不强制共享几何

- 在线目录与新书目录尺寸不同，应分别按各自证据建模。
- 可以共享“封面＋标题＋作者”的语义 schema。
- 不必共享同一个几何模板。
- 允许参数化或明确变体，但不能只因为都叫“图书”，就强行套同一尺寸。
- 本轮也不要求创建原生组件。

#### 6. 停止自动重建的条件

以下情况应保留最小必要固定区域：

- 槽位边界缺失。
- 聚类存在多个同样合理的解释。
- 跨度、重叠关系不明。
- 字体使几何尚未稳定。
- 内容数量不一致。
- 槽位矩形与推导矛盾。

同时保留缺口清单。

### 依据 / 可复现证据

建议实验：

- 核对全部 21 个槽位矩形。
- 比较推导 152×237 与每槽实际值。
- 再以不同起始遍历顺序执行聚类。

预期展示顺序应保持一致。当前没有这些新增实验结果。

### 不确定项

- 全部槽是否等大。
- 真实 DOM 顺序。
- 源布局是否存在 `order`、`reverse` 等规则。

以上均无法确认。

### 失败或放弃的方案

无已核实历史失败。

不采用：

- 未知就默认等宽。
- 用 Figma 顺序冒充 DOM 顺序。
- 人工修正后不留映射。

### 我的备注

- 将 `evidence_status` 与 `layout_status` 分开。
- 推导、测量、布局通过，是三种不同结论。

## R3-D02 grid 等价实现与验证

### 本次实际做法

- 前两轮没有验证单个 grid 的创建、编辑或导出回读。
- 两层 stack 的跨行重组已经明确属于 `regroup-on-rebuild`，不是原生换行。

### 通用做法与 2.0 建议

#### 1. grid 白名单的最低字段检查

当前能力必须确实可以表达目标所需的：

- 行列定义。
- 轨道尺寸。
- gap 和 padding。
- 填充顺序。
- 跨行、跨列。
- 单元格对齐。
- 子项尺寸策略。

逐项记录实际支持，不能只看容器名称或一个 grid 标志。

#### 2. 最低验证范围

**几何：**

- 全部单元格。
- 外边界。
- 空槽。
- 最后一行。

**编辑：**

- 增删。
- 换序。
- 长文本。
- 变宽。
- 跨行传播。
- 装饰定位。

**序列化：**

保存后重开、导出后回读，确认以下内容未丢失：

- 轨道。
- 顺序。
- 尺寸。
- 裁剪。
- 身份映射。

这些当前均属于建议实验。

#### 3. 等价必须按合同定义

- 同一状态下，stack、grid、固定坐标可以只在视觉几何上等价，层数不同可以接受。
- 但如果合同要求原生重排：
  - 固定坐标不等价。
  - 只在重建时重组也不等价。
- 以下差异也不能用“看起来相同”抵消：
  - 文字不可编辑。
  - 换序后身份丢失。
  - 最后一行策略不同。

#### 4. adaptive 原生换行如何选择

不是默认 grid 最好。

- 需要严格二维轨道对齐：选择已验证 grid。
- 一维项目按可用宽度包行：选择已验证 wrap。
- 只要求批量重建时调整：使用重组策略。
- 当前能力不可用时，对“原生换行”这一要求标记 `unsupported`，不能改名冒充实现。

#### 5. regroup-on-rebuild 最低记录

- 旧、新出现键。
- 旧、新行列。
- 旧、新显示索引。
- 旧节点引用。
- 来源矩形。
- 聚类方法与容差。
- 列数、分行策略。
- 输入、输出版本。
- 变更原因。
- 插入、删除、移动、未匹配项。

行 wrapper 可以因为重分组更换身份，但卡片身份不应因为行号改变。

#### 6. 空槽与最后一行规则

至少区分：

- `compact`：按阅读序补齐。
- `preserve-slots`：保留业务槽。

最后一行不能临时 Fill 撑宽。

可以明确约定：

- 固定卡宽。
- 靠起始边。
- 不补造卡片。
- 显式空槽记录为 `empty-slot`。

没有规则时，可以保留当前静态几何，但增删、重排能力应标 `unsupported` 或 `blocked`，不必把整页一律判废。

### 依据 / 可复现证据

建议实验：5 列 10 卡，分别执行：

- 删除第 1 项。
- 删除第 5 项。
- 删除第 6 项。
- 增加第 11 项。
- 跨行移动。
- 保存重开。

核对顺序、最后一行、身份与高度传播。验证的是具体行为，不是仅验证成功保存。

### 不确定项

学生当前环境的 grid、wrap 能力及回读一致性，无法确认。

### 失败或放弃的方案

无新增实验结果。

拒绝：

- 同一帧像素相同，就说明编辑行为等价。
- 重建重组就是原生换行。

### 我的备注

- 白名单需要绑定能力版本、`profile` 和测试范围。
- 某个样例通过，不代表所有 grid 都通过。

## R3-D03 复杂伪元素、SVG 与滤镜支持边界

### 本次实际做法

- 本例没有建立复杂效果的原生支持测试矩阵。
- 以下是建议的保守准入矩阵，不是声称已经逐项支持或验证。

### 通用做法与 2.0 建议

#### 最小支持矩阵

| 类型 | 原生候选最低范围 | 超范围或未验证时 |
|---|---|---|
| 纯色、整体 opacity、简单边框／圆角 | 形状、层级、合成顺序明确 | 保留局部固定结构，复杂混合另测 |
| 线性／径向渐变 | 色标、坐标、裁剪、色彩处理可对应 | 局部栅格化，不用近似默认渐变冒充 |
| 单图背景 | `size`、`position`、`clip` 与缩放可对应 | 记录映射后局部栅格化 |
| 多层背景、平铺 | 各层顺序、定位、裁剪、重复均可表达 | 作为合成区域处理 |
| 简单阴影、blur、drop-shadow | 效果边界、模糊模型、扩展、裁剪验证相符 | 条件候选，不默认 CSS 与 Figma 数值一一对应 |
| multiply、screen 等混合 | 能表达且隔离组、背景、透明度相符 | 条件候选，无对应背景不能单测等价 |
| 亮度、对比、色相等 filter 链 | 逐算子及顺序经过对照验证 | 不直接映射为同名图片调整参数 |
| 矩形、圆角、椭圆 clip | 几何与变换明确 | 可作为裁剪候选 |
| 基本 alpha／vector mask | 类型、单位、嵌套与合成已验证 | 复杂 `mask-composite`、luminance、`clip-path` 局部栅格化或 `blocked` |

#### 1. SVG 边界

简单路径、填色、基本描边、组变换属于原生候选。

以下逐项验证：

- 渐变。
- clip、mask。
- 文本。
- 复用引用。
- 复杂描边。

以下不能默认导入后准确：

- filter。
- `foreignObject`。
- 外部引用。
- 动画。
- 依赖字体的文字。

不是这些特性永远不能原生表达，而是当前未证实等价，就不能进入白名单。可以保留原来源，并在同状态下局部栅格化。

#### 2. 伪元素升级为独立对象的条件

- 承载可见文字、参与排列、提供编号或关键状态、遮挡影响阅读时，应成为独立渲染或语义对象，并关联 owner。
- 纯装饰也需要叠放和裁剪证据。
- 升级为语义对象，不代表承诺交互功能或完整网页可访问性。

#### 3. reference-only 最低字段

- 来源、capture。
- 原始片段及依赖。
- 效果链、叠放。
- 边界、裁剪、变换。
- 栅格化范围。
- 被合并的文字。
- 不可编辑部分。
- 替换所需资源、条件。
- 未支持特性。
- 验收结果。

未知的外部背景不能假装已隔离。

#### 4. 原生与裁片如何选择

- 先满足 `profile` 的硬约束。
- `faithful`：达到误差门槛后，再比较编辑性。
- `adaptive`：如果要求效果参数可编辑，裁片不能算原生效果通过。
- 原生精度不达标、裁片能达标时，可以显式接受视觉降级，同时报告编辑缺口。
- 不能静默选择“看起来差不多”。

### 依据 / 可复现证据

建议实验：每个算子先单测，再测：

- 透明背景。
- 多层叠放。
- 裁剪。
- 组合效果。

对比效果外扩、颜色和遮挡区域。简单单算子通过，不证明效果链通过。

### 不确定项

CSS 与目标渲染器在模糊、色彩、合成上的等价范围，以及学生实际支持项，无法确认。

### 失败或放弃的方案

无已核实历史失败。

不采用：

- 名字相同就等价。
- SVG 导入成功就视觉准确。

### 我的备注

每项记录：

- `native-candidate`。
- `raster-fallback`。
- `unsupported`。

并附依赖条件、版本和证据。原生可表达，不等于本实现已经正确实现。

## R3-D04 无稳定 ID 的重复条目消歧

### 本次实际做法

- 没有建立或验证本例的跨重建自动匹配。
- 前轮只规定了身份分层与 `ambiguous` 状态。

### 通用做法与 2.0 建议

#### 1. 候选匹配优先顺序

首先按已确认的页面、栏目范围限制候选，再依次参考：

- 可靠内容关联，例如规范化详情目标。
- 文字与图片联合指纹。
- 稳定角色锚点与邻域。
- 矩形距离、视觉序号等弱辅助。

不能因位置近，就认定是同一次出现。父路径本身不稳定时，也不能将它当作硬身份。

#### 2. 显式匹配成本，但不伪造权重

- 采用有冲突检测的一对一候选匹配，而不是逐条最近邻。
- 记录：
  - 特征。
  - 特征缺失。
  - 匹配成本。
  - 候选差距。
  - 接受阈值。
- 权重和阈值需要样例标定，本轮不给伪精确分数。
- 唯一且证据充分的匹配，可以保留 `occurrence_key`。
- 只有推测的，应输出 `proposed-match`，不能无声提升为确定身份。

#### 3. 插入、删除、换序如何处理

- 插队、删除、换序本身不必改变已有身份。
- 新出现项新建键。
- 确认删除项保留历史记录。
- 采集覆盖不完整、虚拟列表未遍历时，只能记 `not-seen`，不能认定 `deleted`。

#### 4. 同实体、同栏目重复

只有以下额外证据，才可能稳定区分出现：

- 稳定业务槽。
- 不同来源上下文或关系。
- 持久来源锚点。

两个完全相同副本互换，观察上可能不可辨识。此时必须保留歧义，不能靠序号制造稳定性。

#### 5. 虚拟列表和节点复用

DOM 对象、节点路径不是出现身份。

记录：

- 数据游标。
- 绝对列表位置及来源。
- 分段 capture。
- 可见窗口。
- 节点复用情况。
- 覆盖范围。
- `entity` 与 `occurrence` 分开。

游标、业务身份都未知时，只能提供采集范围内的临时出现键，不宣称跨重建稳定。

#### 6. 必须停止自动匹配的冲突

- 多对一、一对多。
- 同分候选。
- 跨栏目归属不明。
- 内容大幅变化。
- 重要对象可能误替换。
- 弱证据与可靠业务身份冲突。

这些情况需要人工确认。`weak-match` 可以报告低把握关联，不应自动用于破坏性更新。

### 依据 / 可复现证据

建议实验：

- 同名同封面双副本交换。
- 插队。
- 局部采集。
- 虚拟节点复用。

没有额外证据时，系统应该能输出 `ambiguous` 或 `not-seen`，而不是总能生成唯一匹配。

### 不确定项

实际能获得的业务关系、游标和人工确认依据，无法确认。

### 失败或放弃的方案

无已验证历史匹配失败。

放弃“每项必须匹配到旧项”的强制目标，允许未匹配和新身份。

### 我的备注

身份不确定与视觉位置变化是不同问题。位置变化可以确定，身份对应仍可能未知。

## R3-D05 full-page 与 sticky 的同态验证

### 本次实际做法

- 此前没有提供全页捕获机制的完整状态记录。
- 不能断言原截图采用了某种拼接，也不能断言所有 sticky 区域都与 DOM 同态。

### 通用做法与 2.0 建议

#### 1. 定义三类参考

- 单视口状态。
- 保持原视口的文档捕获。
- 逐段合成参考。

分块拼接与扩展视口，默认不等同。只有相关布局、媒体条件、视口单位、sticky、fixed 和加载状态经证据证明等价，才允许在该范围比较。

#### 2. 拼接不伪称全局同时状态

每段记录：

- `capture_id`、`segment_id`。
- 时间。
- 视口。
- 滚动。
- 裁剪、拼接变换。
- 重叠区。
- 字体、资源和状态。

每段做 M0／S／M1，再验证跨段不变量和接缝。全局参考标记 `composite`。

#### 3. sticky、fixed 的位置变化

- 随滚动发生的变化可以符合捕获合同，但不能拿 M0 滚动位置的矩形，直接对另一段 S。
- 每段应对应同一滚动状态。
- 固定头是：
  - 只保留一次。
  - 重复出现。
  - 被隐去。
  - 必须显式记录。
- 未经授权改变显示、不明原因漂移、接缝重复或缺失，均不能判同态通过。

#### 4. 需要比较的信号

- 各段实际视口、媒体条件。
- 视口单位相关区域尺寸。
- fixed 背景相位、定位。
- sticky 锚点。
- 实际图源、自然尺寸。
- 重叠区匹配。
- 段间文本和对象身份。
- 累计拼接变换。

只比总页高不够。

#### 5. 0.5 CSS px 不自动适用于所有区域

它只是约定坐标系下，局部关键矩形的起始门槛。

不能直接用来判定：

- 拼接误差。
- 字形误差。
- 全页所有区域。

长页应分层覆盖：

- 页头、页尾。
- 所有接缝。
- sticky。
- 懒加载边界。
- 重复区域。

同时报告采样覆盖。不能因为页面长就允许累计漂移，也不能把未采样区域算作通过。

#### 6. 部分同态如何限制结论

报告：

- 有效区域。
- 无效或未知区域。
- 各段参考。
- 原因。

有效区可以支持局部几何结论。

不能用它推断：

- 跨接缝 gap。
- 全页总高。
- 全局顺序。
- 跨状态尺寸传播。

核心布局依赖这些关系时，转换应 `blocked`，不能拿 `partial` 支持整页 `verified`。

### 依据 / 可复现证据

建议实验：同页分别采用原视口滚动拼接和扩展视口捕获，加入：

- `100vh` 区域。
- fixed 背景。
- sticky 头。
- 懒加载内容。

逐段比较，不能只比较长图尺寸。

### 不确定项

原页面捕获过程、各环境 full-page 行为和接缝误差分布，无法确认。

### 失败或放弃的方案

无新增实验。

不以同 URL、同页高或全局 hash 相同，替代局部同态验证。

### 我的备注

参考状态可复现，不代表浏览器瞬间真的显示过那张合成长图。报告要区分文档目标与捕获产物。

## R3-D06 `normal`、基线测量与字形阈值

### 本次实际做法

- 没有测量本例真实 used 行盒、逐 run 基线或跨渲染器字形阈值。
- 前轮 0.5／1 CSS px 均只是起始参数。

### 通用做法与 2.0 建议

#### 1. normal 需要多方法交叉

标准 DOM 接口并不普遍直接暴露完整 used 行盒和每行基线。

保留 `normal` 声明，交叉参考：

- 容器矩形。
- 文本 Range 矩形。
- 相邻行进距离。
- 实际字体 run。
- 字体度量。

但：

- Range 是片段矩形，不能改名为准确行盒。
- 字体或 Canvas 度量，不能单独代表 CSS 行高。

#### 2. 基线探针仅作为受控实验

- 在受控副本中，可以使用零尺寸、基线对齐的内联探针，辅助定位 alphabetic baseline。
- 前提是验证探针没有改变：
  - 行高。
  - 换行。
  - 布局。
- 并恢复原内容。

这是建议实验，不是本轮已执行或普适无扰动方法。若可用排版诊断提供直接证据，应记录方法和版本。

#### 3. 中文基线必须说明定义

采用的是：

- alphabetic。
- ideographic。
- 其他基线。

必须明确。可见字形底边不是基线。

- 多行：逐行记录。
- 混合 run：区分行基线与 run 偏移。
- 上标、下标、不同字体：不能只用整段一个值。
- 单行 `normal`：没有行距旁证，行高和基线可能仍未知。

#### 4. 拿不到基线时哪些项不能验收

没有可靠源或输出基线时，以下记为 `not-evaluated`：

- 基线偏差。
- 逐 run 垂直对齐。
- 由基线推导的精确行盒结论。

内容、换行、可见字形和边界仍可独立检查。不能据此补出“基线误差 0”。

#### 5. 阈值如何标定

固定：

- 字体二进制、版本、可变轴。
- 字号、字重。
- DPR。
- 浏览器版本。
- 输出渲染版本。
- 色彩条件。

字符至少包括：

- 常见中文。
- 全角标点。
- 拉丁大小写。
- 数字。
- 中英混排。
- 省略号。
- 粗斜体。
- 缺字。
- emoji 另测。

先估相同环境重复捕获的噪声，再比较跨渲染器分布。分角色报告边缘、行进、换行和粗细差异，不使用一个像素通过率覆盖全部。

#### 6. 字体不可用、未获准替换时

输出：`blocked-font / partial`。

保留：

- 文本内容。
- 原始字体声明。
- 矩形。
- 证据。

已有原生文本可以不改动地保留，并标未验收。

没有可用字体、也没有替换授权时，不能承诺新建了正确排版的 Figma 文本层。提供字体或获准替代后，再生成可编辑草稿，明确 `draft / fallback`，不用隐式替换伪装 1:1。

### 依据 / 可复现证据

建议实验：

- 同一字符串分别采用单行、多行、混合 run，比较探针前后的矩形和换行。
- Range 边界、字体度量、探针基线分别记录，检查是否矛盾。

### 不确定项

具体环境的可靠基线证据、中文字体版本和经标定阈值，无法确认。

### 失败或放弃的方案

不采用：

- Range 底部减常数。
- 字形底边当基线。
- 统一 1.4em 当实测。
- 未获准就换字体。

### 我的备注

“保留可编辑文本”与“准确原字体排版”可以分别交付或分别阻塞。信息与授权不足时，不能同时宣称两者已经完成。
