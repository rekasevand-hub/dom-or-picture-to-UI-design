## R1-Q01 三块画板是否来自同一套生成流程？

### 本次实际做法

- 无法确认是否为同一实现版本，也不能认定来自同一套固定流程。
- 能确认的是三次重建分别使用了不同主要依据：
  - 上传截图路线：以用户图像为准进行可编辑重建。
  - URL 自主截图路线：访问网站并捕获页面后据图重建。
  - DOM 路线：额外获取文字、部分计算样式、矩形尺寸和图片资源，再据此重建。
- 三次没有事先执行统一的层级、命名和布局规范。
- 输入来源不同是已知条件；底层实现版本相同或不同是另一个命题，现有成品不能证明，不能用结构差异反向证明版本变化。

### 为什么 URL 自主截图版大量使用 Auto Layout，而上传截图版完全没有？

- 无法确认生成时的具体原因。
- 能观察到前者采用较多嵌套布局容器，后者使用固定坐标区域。
- 截图输入本身既不要求使用 Auto Layout，也不禁止使用 Auto Layout。
- “没有统一结构规范”是已确认的交付约束缺失，但不能进一步断言每个容器的布局设置都由这一因素导致。

### 如果只能选一块作为 2.0 的结构基线

建议选 **DOM 版**作为“可追溯的几何与资产起点”，但不是最终布局模板：

- 原始资源可独立替换；
- 尺寸依据较明确；
- 便于把精度问题与布局规则问题分开验证；
- 内部固定坐标和 spacer 需要改造，不能照搬。

如果不是单一基线，建议按维度各取所长：

- **几何与素材**：以同一视口、同一显示状态下的 DOM 测量和原始资源为准。
- **布局组织**：从 URL 自主截图版选择已核实的多子项排列和内容自适应模式，必须经过扰动测试；不按 Auto Layout 数量选优。
- **视觉验收**：以该轮指定的唯一参考图为准；不同截图里的轮播、懒加载和裁切状态不能拼成一个假定的共同真值。
- **命名和层级**：重新按 Q06 制定，不继承任何一版的全部结构。

### 字体差异

- 题内字体设置差异作为事实接受；具体选择原因无法确认。
- 不能归因于某一种模型或固定路线规则。
- 文本层声明 Inter 不证明中文字符由 Inter 提供字形，也不证明原网页实际使用 Inter。
- 应分开记录：声明字体、实际字形回退、字体可用性、文本排版结果。

### 通用建议

- 固定视口、显示状态、字体环境和验收参考，再比较输入路线。
- 2.0 应统一结构输出规范，只让证据来源不同，不让分组策略随路线任意变化。

### 依据 / 可复现证据

- 题内三版统计。
- 当前 DOM 根容器为纵向布局，URL 自主截图根容器也为纵向布局，上传截图根容器及内部没有 Auto Layout。

- 可复现实验：固定同一图像、同一字体和同一结构规范，分别构建多次，比较层级、布局行为与几何误差。当前三块画板不是受控的因果对照实验。

### 不确定项

历史实现版本、具体字体选择动机、所有构建步骤及中间尝试；无法确认。

### 失败或放弃的方案

## R1-Q02 URL 自主截图版的 220 个 `stackMode` 是真布局还是结构标记？

### 本次实际做法

“真流式 / 结构标记”二分不够准确，应至少分为：

1. **多个在流子项参与排列**；
2. **单个在流子项**，仍可提供居中、内边距和内容适应；
3. **零个在流子项**，仅用于裁剪或叠放。

本次补查结果：

- 220 个 Auto Layout Frame 中，133 个有至少两个在流子项；
- 43 个有一个在流子项；
- 44 个没有在流子项。
- 题内按“全部子项数”分类的 133/87 中，87 个单子项容器里有 44 个子项实际是 `ABSOLUTE`。

结论：

- 第一类有真实排列约束，但是否满足内容变化后的设计意图仍待测试。
- 第二类不能简单称为“假布局”。
- 第三类虽开启布局，但不承担子项之间的流式排列，可列为移除冗余布局设置的候选。

### 如何判断一个容器是否应该开启 Auto Layout？

通常看是否存在可表达的排列、对齐、间隔、内边距或内容驱动尺寸关系，而不是只看命名或子项数量。2.0 的具体准入条件见 Q03。

### 子项内容高度变化时，哪些容器会重排？

- 纵向流会依据直接在流子项的实际高度重新排列后续兄弟。
- 但文字变化只有在改变了其所在直接子项高度时，才能继续向外传播。
- 固定高度卡片里的文字增长可能只是溢出或被裁切。
- `首页内容` 中的某一直接栏目实际增高后，后续栏目会下移，父容器随之增高并可继续向外传播。导师描述为 Hug 高度；`.fig` 字段为 `null`，该点需按上条注记复核。
- 横向 Auto Layout 不等于纵向响应式重排；固定高度与未开启换行仍可能导致溢出。
- 绝对子项不挤开兄弟，也不贡献正常流尺寸。

### 打开布局后是否遇到过位置漂移？

- 无法确认历史上是否发生以及具体表现；当前最终状态不足以证明“曾漂移又修复”。
- 可预期风险包括：字宽变化、Fill 重分配、居中基准变化、间距取整。
- 这些属于待验证风险，不是本次失败记录。

### 通用建议

- 分别记录：在流子项数、绝对子项数、尺寸策略、对齐与换行。
- `stackSpacing=null` 仅表示该导出字段未显式给值，不能据此认定布局无效；应结合运行时属性或可靠默认值。
- 将“设置为 Auto Layout”“布局引擎实际参与”“扰动后行为正确”分成三级验收。
- 不用 `stackMode` 数量作为结构质量分数。

### 依据 / 可复现证据

- 上述容器参数已只读核实。
- 建议在测试副本中将一直接栏目高度增加 40：纵向后续兄弟应下移 40。
- 另将裁剪容器的绝对图片增高 40，外层占位应不因此增长；后一个行为正是裁剪容器的职责，不是错误。
- 本轮未执行该扰动实验，也未改变学生画板。

### 不确定项

全部 220 个容器在不同宽度、长文本下的行为；未通过实验验证。

### 失败或放弃的方案

无已知记录。建议放弃“一个子项就是假布局”“有 `stackMode` 就一定可重排”这两个分类标准。

### 导师补充

真布局不必然是好布局；截图还原准确也不必然有正确的内容适应行为。

## R1-Q03 DOM 版为什么只开最外层 Auto Layout？

### 本次实际做法

- 当时具体选择原因无法确认。
- 已核实结果：外层纵向 Auto Layout、11 个固定尺寸在流子项，内部 124 个 Frame 依赖局部坐标。
- 该结构适合保存固定视口的一帧几何，但“适合”不是历史动机的证据。
- 不能声称 DOM 自动转换了完整布局；本次只是 DOM 测量支持的几何重建。

### 是否尝试过内部 Auto Layout？

无法确认。没有可核实的前后状态和失败记录，不能把当前固定坐标解释为失败后的退路。

### 2.0 栏目级 flow 候选条件

建议条件：

1. 语义上有明确先后顺序。
2. 在流内容沿单一主轴排列，重叠只属于可单独识别的背景/装饰。
3. 父子关系、有效内容数量和视觉顺序一致。
4. 间隔、内边距、对齐及尺寸策略可明确表达。
5. 字体、文字宽度与素材尺寸已稳定。
6. 无 Hug 依赖 Fill、Fill 又依赖 Hug 的未解尺寸循环。
7. 能明确说明内容增高后哪些兄弟应该移动。

网格或多列：

- 先建立“行/列/侧栏”层，再验证每层；
- 不要将所有后代一次塞进一个线性布局。
- 像素级共享边框、负间距、叠放等不能表达或验证失败时，保留最小固定坐标区域，并记录原因。

内部固定坐标规则：

- 所有位置以所在固定容器为坐标系；
- 记录容器矩形、子项局部矩形、裁剪范围与锚点；
- 只将装饰和叠放子项排除在流外；
- 不将主体文字偷偷移到绝对定位以掩盖布局错误。

### 开启后位置漂移的回退建议

- 在副本中转换；
- 转换前保存父子层级、顺序、尺寸、变换、约束、裁剪及文字排版参数；
- 先固定新布局的外部矩形，再由内到外、逐层启用；
- 验收不通过时优先保留原子树、丢弃候选子树，而不是反复修补已漂移坐标；
- 若必须原位恢复，应关闭布局并恢复原层级、局部矩形及相关属性；
- 有旋转/嵌套缩放时需要变换矩阵换算，不能仅做坐标相减；
- 从无旋转、无缩放的全局 DOM 矩形转成局部坐标时，使用“子项左上角 − 父容器左上角”，并统一滚动偏移、边框基准与 CSS px 尺度。

### 没有自动回退时如何保证外观不漂移

- 不能仅靠开启前的判断保证，必须在测试副本对比实际排版结果。
- 没有验证能力时，保留原稿并把候选标为未验收，不宣布转换成功。
- 固定视口验收建议：
  - 关键容器和文字框边界误差不超过 **1 CSS px**；
  - 截图缩放比例为 `s` 时，相应画布阈值为 `s px`；
  - 换行行数、内容数量、显示状态必须一致；
  - 图片保留纵横比，不以平均误差掩盖少量大偏移；
  - 文字基线与可见字形另做检查，边界框一致不代表字形一致。
- 内容测试：
  - 某在流栏目实际增高 40 CSS px 后，预期下游偏移 40；
  - 标题变长；
  - 宽度 ±10%。
- 这些是建议测试输入，不是原站响应式要求。

### 通用建议

- 先固定参考几何，再推断约束，最后用扰动实验判定约束是否成立。
- 原稿、候选稿、验收结论分离。
- 不要把“能看起来一样”当作“布局规则正确”。

### 依据 / 可复现证据

- 当前 DOM 根容器：`VERTICAL` / `FIXED×FIXED`、间距/内边距 0、11 个在流子项、无绝对子项；直接子项高度合计 2545；其余 Frame 未开启布局。

## R1-Q04 空白间隔 Frame 是否是推荐模式？

### 本次实际做法

- 当前确实存在 5 个间隔 Frame；产生动机无法确认。
- 不能从成品判断是有意设计还是构建方式的结果。

### 2.0 建议

通常：

- 等距同级项用 `itemSpacing` / gap；
- 容器外沿用 padding；
- 有差异的区段采用必要的语义容器或明确的边缘间距。

对本页 2.0，建议：

- 将前 5 个内容区放入纵向内容容器，4 个区间设为 20；
- 页面根容器连接该内容容器与页脚，间距设为 50；
- 这样表达原来的 20/20/20/20/50，不需要 5 个空白节点。
- 这是建议的新结构，尚未实施。

### gap/padding 与 spacer 的取舍

gap/padding 优点：

- 层级干净；
- 增删栏目方便；
- 间隔不易被误选。

gap/padding 缺点：

- 单一 gap 无法表达任意不同间距；
- 可能需要额外但有职责的容器。

spacer 优点：

- 可直观表达不规则或可伸缩占位。

spacer 缺点：

- 引入无内容节点；
- 容易孤立、重复、被误删；
- 可能在重排时落到不合适的位置。

仅在“占位”本身具有明确职责时保留 spacer，并标明固定/弹性策略。

### 栏目高度变化时

- 若栏目实际高度能向外传播，在流 spacer 仍会保持固定空隙，不是技术错误；
- 但它不能解决栏目内部的固定高度与溢出问题；
- 响应式重组时，旧 spacer 往往不再对应正确的语义边界，应重新布局。

### 通用建议

- 优先 gap/padding；特殊占位允许例外。
- 不要为了“零 spacer”目标引入更多无职责 wrapper。
- 也不要用 gap 冒充外沿 padding。

### 依据 / 可复现证据

- 高度为 20；题内其余三处栏目前间隔为 20，页脚前为 50，根 gap/padding 为 0。
- 新结构验收需使全部内容区起点与旧版一致。

### 不确定项

历史设计意图无法确认。

### 失败或放弃的方案

无历史记录。建议不采用“所有区间硬设同一个 20，再对页脚做绝对偏移”的修补方案。

### 导师补充

spacer 并非一律错误，本页只是可以用更清晰的结构等价表达。

## R1-Q05 原图 vs 全页截图复用，如何取舍？

### 本次实际做法

- 截图路线实际采用的是：多节点引用同一全页图，再显示局部；不是每个封面都有独立图片字节。
- 不能把它描述为“已提取独立素材”。

### 裁剪机制

本轮抽查的两种截图路线均为：

- 大图子项使用 `IMAGE/FILL`；
- 局部位置为负偏移；
- 父 Frame 固定尺寸并开启 `clipsContent`；
- 抽查项没有作为 mask 使用；
- 图片变换矩阵为单位矩阵。

可对应的抽查例：

- URL 版 `读书网标志`（1:368）：270×60 的裁剪窗口；内层全页图节点 1440×2550，局部位置 `(-124,-54)`。
- URL 版 `京东图书活动`（1:402）：190×100 窗口；图节点位置 `(-724,-196)`。
- 上传截图版 `智囊全集封面`（1:828）：窗口约 158.69×208.28；内层图片节点 2544×4959，局部位置约 `(-1787.74,-3992.05)`。

以上只证明抽查项的机制，不将抽查扩张为全部节点的逐项核实。URL 图节点高 2550，而题内原图高 2545；`FILL` 可能带来缩放/裁切差异，应核对实际采样，不能按完美 1:1 像素裁剪处理。

### 为什么不把每个书封/横幅切成独立图片？

- 本次未这样做的具体原因无法确认。
- 共用全页图能避免生成大量资产，并保持取样来源统一，是一般性的取舍解释，不是历史动机证据。

2.0 建议：

- 若需要独立替换/导出，优先原始资源；
- 只有截图时，可按素材边界生成真正独立的裁片；
- 无须编辑的视觉参考也可以保留共享图裁剪，但必须明确标注。

### 对编辑性、文件大小、导出和替换素材的影响

编辑性：

- 裁剪窗口可编辑；
- 图像内部仍是像素，不能拆出封面上的文字；
- 替换素材需同时处理大图尺寸、偏移与裁剪，不能直接当作普通书封替换。

大小：

- 同一 `imageHash` 多次引用不等于按引用次数重复保存整张位图，不能宣称文件大 44 倍；
- 但节点、裁剪与渲染开销增加；
- 独立裁片也未必使总文件更小，取决于压缩、重复内容和分辨率。

导出：

- 应导出裁剪窗口，避免直接导出内层大图；
- 引用全页图也会保留无关区域的图像数据；
- 对只需局部资产的交付应去除无关像素；
- 不能把裁剪当作数据脱敏。

建议以相同输出尺寸测试：打开/导出耗时、资产字节总量、单封面替换步骤；不以节点数量估计文件体积。

### DOM 路线是否始终优先原始资源？

- 本次 DOM 版使用了独立原始资源，但不能外推为“始终执行”的固定规则。

建议回退顺序：

1. 同状态的原始资源，图标优先准确矢量。
2. 匹配显示状态的其他合法可访问原资源。
3. 从权威截图按素材边界裁取独立图片。
4. 必要时共享全页图裁剪并标记来源。
5. 简单 UI 用原生形状/准确图标重建。
6. 复杂封面和品牌图不能随意重画或用相似图片替代。
7. 若素材仍不可得，保留参考中真实占位状态或明确标为缺失，不静默补造。
8. 原站图像与截图状态不一致时，忠实截图任务以截图为准。

### 占位封面差异

- 无法确认该差异的具体原因；本轮没有逐位置的源图/导出图对照清单。
- 此前读取的两张来源截图在部分封面的加载状态不同，不能仅凭路线名称判断谁已加载、谁未加载，也不能排除裁剪坐标/缩放错误。
- 原页面存在懒加载是已知线索，但不足以证明每处差异均由懒加载导致。
- DOM 采样曾保留 21 处占位图；“占位图可成功解码”也不等于原封面已加载。

建议先明确任务：

- 复现指定截图：保留它的加载状态；
- 采集稳定网页：固定视口与缩放、逐段滚动触发加载、等字体与目标图片解码、检查实际图源/自然尺寸及页面特定占位地址、等待过渡结束、返回目标位置并再核对布局。

补充：

- `networkidle` 或固定等待若干秒均不是加载完毕的充分条件；
- 应记录每个目标图片的期望地址、实际地址与失败/占位状态；
- 对轮播冻结目标帧；
- 连续两次稳定采样可作为必要检查之一，但“稳定显示占位图”仍不算资源成功。

### 通用建议

- 分开管理“来源像素”“独立资产”“裁剪窗口”和“Figma 布局节点”。
- 资产记录至少包括：来源、原始尺寸、裁剪矩形、缩放、显示状态、能否独立替换。
- 截图像素尺寸不自动等于 CSS px；记录设备像素比和缩放。上传截图无法确定这些值时，使用图像像素坐标，不伪造网页 CSS 尺寸。

### 依据 / 可复现证据

- 题内唯一图片数与填充次数；
- 本轮上述裁剪参数；
- 可在测试副本关闭父级裁剪查看全页内容，或单独导出窗口与内层图进行对照；本轮未执行修改。

之前关于“保留原站图片”的表述需收窄：截图路线保存的是截图中的图片像素，不等于拿到了图片的原始独立资源。

### 不确定项

各处图片状态差异的具体归因、原图加载完成判据在此前是否全部满足、共享/切片方式的实际性能差异。

### 失败或放弃的方案

无可核实的“独立切片尝试失败”记录。2.0 不采用共享全页图且不记录裁剪关系的隐式方案。

### 导师补充

图片“可见正确”“可独立替换”“来源可追溯”是三项不同指标，分别验收。

## R1-Q06 统一层级与命名规范

### 为什么三块画板分组粒度不同？

- 已确认三次没有统一的结构规范；每个具体合组决定的历史原因无法确认。
- 输入证据不同会影响可推断信息，但不能作为所有差异的充分解释。
- 不是“截图必须粗分组、DOM 必须细分组”。

### 建议的统一层级

最低规范：

`页面 → 独立栏目 → 列表/卡片 → 图片、标题、作者`

建议扩展为：

`页面 → 页面区域 → 独立栏目 → 内容集合/布局行列 → 重复卡片 → 内容元素`

说明：

- 不是每个节点必须经过全部层级；无职责的空层应省略。
- 栏目标题和列表是栏目下的兄弟。
- 左侧新书栏目与右侧推荐栏目是布局行下的兄弟，不能只因并排就当成一个语义栏目。
- 列表可包含多张卡片；卡片本身保留封面、标题、作者等语义元素。

### Frame、Group 与 wrapper

- **Frame**：需要明确尺寸、背景、边框、裁剪、布局或约束时使用。
- **Group**：仅需一起选择/移动且没有独立布局与裁剪职责时使用；不作为未来布局容器的替代。
- **wrapper**：仅在承担具体职责时存在：控制列宽、行列排列、素材裁剪、对齐槽位或独立变换。
- 单子项 wrapper 可以合理；不能只因“层级看起来整齐”而新增。
- 布局与裁剪职责宜分离：例如封面槽位控制对齐，内部图片控制裁切；若一个 Frame 已可清晰承担二者，则不强制再套一层。

### 页头、焦点区、页脚、浏览器滚动条

- 页头、焦点区、主内容、页脚各自独立。
- 页头内部可分工具栏/品牌搜索/导航。
- 焦点内部可分轮播/广告/分类。
- 浏览器滚动条不属于网页业务内容。
  - 若任务要求复现整张截图，放在独立“截图外观层/浏览器界面”中，排除在网页内容 flow 之外；
  - 若目标是网页设计稿，不包含浏览器界面；
  - 用户上传图中的元素不能在未说明时静默删除。

### 命名规则

建议采用“可读语义名 + 可选稳定语义键”：

- `在线读书 / section.online-reading`
- `图书卡片 / book-card`
- `封面 / cover`
- `标题 / title`
- `作者 / author`

序号只用于重复项定位，并保留内容标识，不作为语义身份。  
节点 ID 用于当前版本证据定位，不应作为跨重建的稳定身份；名称不承载全部状态。  
单独记录 `source`、`asset`、`geometry`、`layout`、`confidence` 等映射信息；`confidence` 若无校准只用“已测/推断/未知”，不编造概率。  
避免“内容”“图书位置”“Frame 123”作为最终唯一名称；同名重复项须能通过父级和内容标识辨认。

### 通用建议

- 统一的是职责与层级规则，不是强制相同 Frame 数量。
- 视觉坐标区、语义栏目、素材裁剪区可以不同，但应有明确映射。

### 依据 / 可复现证据

- 题内三版分区清单。原文此处引用的具体节点/区域名在纯文本传输中丢失；按题内清单，上传截图版把“页头与焦点”“国学古籍/阅读排行/页脚”合并，跨越了建议的独立页面区域，应作为重整对象，而不是统一规范的样板。该对应是依据已知分区做出的最小还原，不冒充导师原话。
- 验收例：只替换一本书的封面或增加作者一行时，能够通过栏目/卡片/内容角色定位，不需要搜索整页截图或修改其他栏目。

### 不确定项

历史命名与分区使用了哪种识别路线，无法确认；本次结果不能证明存在固定分区算法。

### 失败或放弃的方案

无历史记录。建议不采用强制固定树深、依赖节点 ID 跨版本匹配、以及按视觉邻近无限合组的方案。

### 导师补充

结构的质量取决于是否支持实际编辑任务，而不是树越深或命名越长越好。

## R1-Q07 失败模式与不推荐照搬的部分

### 三条路线各自最大的 3 个失败模式

以下是结合本例提出的优先验证风险，不是有统计依据的失败率排名，也不是都已在本次发生。

**上传截图**

1. 字体/文字度量未知，近似字形与折行不匹配。
2. 整页图裁剪代替独立资产，导致后续替换困难或裁错区域。
3. 把视觉邻近当语义关系，或把浏览器界面混入网页 flow。

**URL 自主截图**

1. 视口、轮播、懒加载时机不固定，参考状态不一致。
2. Auto Layout 的均分、Hug/Fill 等推断改变原始几何，形成“结构整齐但外观不准”。
3. 仅有截图像素却误宣称拥有原始素材、真实字体或响应式规则。

**URL DOM**

1. DOM 矩形重建被误认为完整 CSS 布局迁移。
2. 字体加载、实际字形回退、伪元素/变换/共享边框等信息不全，导致测量与渲染不一致。
3. 固定内部高度阻断内容传播，表面有 Auto Layout 但编辑后仍重叠/裁切。

### 尝试过但放弃的做法

- 对结构、分组、字体测量和资产策略，没有可核实的失败尝试记录，回答“无法确认”。
- 可确认的是采集时曾遇到页面请求超时、浏览器证书校验和缺少中文字形等环境问题，随后取得了截图与测量。
- 这些不证明任何内部 Auto Layout 方案失败，不能把环境重试当作结构策略的消融实验。

### 不建议照搬的部分

**DOM 版**

- 5 个无语义 spacer；
- 几乎所有内部容器都固定坐标；
- 根高度固定却未定义内容增高后的边界策略。

**URL 自主截图版**

- 所有图片局部都依赖同一全页图且缺乏独立替换关系；
- 44 个仅含绝对大图的容器也开启 Auto Layout；
- 导航被改成等宽分配，而此前网页测量显示原导航并非等宽。`[FIG]` 复核：`主导航` 6 个链接均为 `stackChildPrimaryGrow=1`，宽度约 198.33。

**上传截图版**

- 跨区域合组；
- 固定坐标作为唯一结构；
- 统一 140% 行高和替代字体未逐项校准；
- 当前使用实际字体不等于已经按原站字体实测定位。

**三版共同**

- 未做完整像素与编辑行为验收就称为“1:1”；
- 未完整附带每个元素的来源与不确定项。

上述是应修正的交付边界，不是否定已有重建内容的全部价值。

### 如果只能给 2.0 一句最重要的结构建议

> 以可追溯的固定几何保底，只把能通过原始外观与内容扰动双重验收的关系升级为 flow；语义层级不随输入路线任意改变。

### 通用建议

把验收拆成四项：**视觉还原、结构语义、编辑行为、资产可替换性**；分别报告，不能以某一项代替全部。

2.0 实施顺序：

1. 锁定参考状态；
2. 建立资产/文字/矩形清单；
3. 统一语义骨架；
4. 选择局部 flow 候选；
5. 副本转换与对比；
6. 扰动验证；
7. 保留通过项、回退失败项；
8. 记录未决问题。

建议测试集至少覆盖：一张卡片标题加长、某栏目实际增高、单封面替换、窄幅布局变化、源图缺失、占位图加载成功但原封面未加载。保留每个测试的预期与实际结果。

### 依据 / 可复现证据

- 本回答 Q02–Q06 的节点与参数，以及题内解析统计；已核实的属性只能支持结构结论，不能支持误差分数或失败率。
- 上传截图版曾只读检查到 160 个文本层、统一 140% 行高、Noto Sans SC 和高度自动增长；这支持“未呈现分角色行高规范”的结论，不证明每处文字都排错。

### 不确定项

未完成全量像素差分、基线校准、扰动实验和性能测试；不能给三版发布严格的综合排名。

### 失败或放弃的方案

无其他可核实历史记录。2.0 明确不复制：

- 全局一键 Auto Layout；
- 把所有多行文字统一 140% 当作精确复刻；
- 隐式共享大图裁剪；
- 用默认样式替换未知项却不报告。

### 导师补充

不要把这三张样例直接当作可泛化算法的证据。应从它们提取可测试假设，再用同源、同状态、同规范的样例验证。
