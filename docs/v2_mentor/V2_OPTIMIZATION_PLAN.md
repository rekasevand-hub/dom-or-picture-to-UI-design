# Figma Auto Agent 2.0 优化实现方案

> 状态：讨论中。R1、R2、R3 已收敛的决策已写入；所有 DOM 节点与截图布局仍停在 `candidate / fixed-retained / unsupported`，未做扰动与阈值标定。  
> 来源：导师问答（`ROUND_01_ANSWERS_FORMATTED.md`、`ROUND_02_ANSWERS_FORMATTED.md`、`ROUND_03_ANSWERS_FORMATTED.md`、`ROUND_03_DOM_ANSWERS_FORMATTED.md`）、`.fig` 证据（`ROUND_01_FIG_INVENTORY.md`）、V1.1.0 代码与实验。  
> 原则：只有能落成可测试规则、参数或验收标准的结论，才进入本文档。

## 1. 目标与边界

### 1.1 2.0 目标

1. **DOM → Figma 变强：** 保留 DOM 几何与原始资产的精度，同时建立可编辑的语义层级；只在通过静态与扰动验收的容器上启用 true flow。
2. **URL 访问有退路：** 目标内容可直接访问时走 DOM；无头被重定向/反爬挡住但真实会话能看到内容时，自动转“自主截图 → 截图复刻”；目标页本身是登录页时停止，并提示登录或手动上传截图。
3. **截图 → Figma 独立成线：** 先单独做好“截图 → Figma”，不与 DOM 路线融合；融合等两条路线稳定后再讨论。
4. **交付可验收：** 视觉还原、结构语义、编辑行为、资产可替换性四项分别报告，不用一项代替全部。

### 1.2 非目标

- 不追求“Auto Layout 数量最大化”。
- 不把全部容器一键转 Auto Layout。
- 不在没有扰动实验的情况下宣称 true flow 或“像素级 1:1”。
- 不把 DOM 与截图路线提前融合。
- 不从三块导师样例反推历史版本、失败记录或内部实现。
- 不为“看起来整齐”增加无职责 wrapper。

## 3. 结构规范

### 3.1 层级

统一采用：

```text
页面
→ 页面区域
→ 独立栏目
→ 内容集合 / 布局行列
→ 重复卡片
→ 内容元素
```

不是每个节点必须经过全部层级；没有职责的空层省略。

### 3.2 判断规则

- 栏目标题和列表是栏目下的兄弟，不是父子。
- 左侧新书栏目与右侧推荐栏目是**布局行**下的兄弟，不能只因为并排就当成一个语义栏目。
- 列表包含多张卡片；卡片保留封面、标题、作者等内容元素。
- 页头、焦点区、主内容、页脚各自独立；页头内部可分工具栏/品牌搜索/导航，焦点内部可分轮播/广告/分类。
- 浏览器滚动条不属于网页业务内容：复现整张截图时放在独立“截图外观层/浏览器界面”，排除在网页内容 flow 之外；网页设计稿不包含它。
- 用户上传图中的元素不能在未说明时静默删除。

### 3.3 Frame / Group / wrapper

- **Frame**：需要明确尺寸、背景、边框、裁剪、布局或约束时使用。
- **Group**：仅需一起选择/移动且没有独立布局与裁剪职责时使用，不作为未来布局容器的替代。
- **wrapper**：只在承担具体职责时存在：控制列宽、行列排列、素材裁剪、对齐槽位或独立变换。
- 单子项 wrapper 可以合理；不能只因“层级看起来整齐”而新增。
- 布局与裁剪职责宜分离：封面槽位控制对齐，内部图片控制裁切；若一个 Frame 已可清晰承担二者，则不强制再套一层。

### 3.4 读书网首页示例

```text
页面
├─ 网站页头
│  ├─ 欢迎栏
│  ├─ 标志与搜索
│  └─ 主导航
├─ 焦点与分类
├─ 在线读书
├─ 新书与推荐（布局行）
│  ├─ 新书目录（栏目）
│  │  ├─ 栏目标题
│  │  └─ 图书行（内容集合）
│  │     └─ 图书（重复卡片）
│  │        ├─ 图书封面
│  │        ├─ 书名
│  │        └─ 作者
│  └─ 推荐排行（栏目）
├─ 国学与阅读排行
└─ 网站页脚
```

> 注：示例中的 `图书行` 来自 URL 版观察样本；DOM 版 `1:243 新书目录` 当前是 5×2 扁平网格，右栏还有 `1:212 图书推荐` 容器。`R2-Q01` 已建议重建行/列表层与左栏 wrapper；结果仍只是 `candidate`。

### 3.5 命名

采用“可读语义名 + 可选稳定语义键”：

- `在线读书 / section.online-reading`
- `图书卡片 / book-card`
- `封面 / cover`
- `标题 / title`
- `作者 / author`

规则：

- 序号只用于重复项定位，不承担语义身份。
- 节点 ID 只用于当前版本证据定位，不作为跨重建身份。
- 同名重复项必须能通过父级和内容标识辨认。
- 禁止“内容”“图书位置”“Frame 123”作为最终唯一名称。
- 具体重复项语法、稳定键组成与存放位置见 12.6；无稳定 ID 的消歧规则见 13.1.4，匹配权重仍待样例标定。

## 4. Auto Layout / flow 规范

### 4.1 静态门

一个容器只有同时满足以下条件，才进入 flow 候选：

1. 语义上有明确先后顺序。
2. 在流内容沿单一主轴排列，重叠只属于可单独识别的背景/装饰。
3. 父子关系、有效内容数量和视觉顺序一致。
4. 间隔、内边距、对齐和尺寸策略可明确表达。
5. 字体、文字宽度和素材尺寸已稳定。
6. 没有 Hug 依赖 Fill、Fill 又依赖 Hug 的未解尺寸循环。
7. 能明确说明内容增高后哪些兄弟应该移动。

网格或多列必须先建立“行/列/侧栏”层，再逐层验证；不能把所有后代一次塞进一个线性布局。像素级共享边框、负间距、叠放等无法表达或验证失败时，保留最小固定坐标区域并记录原因。

### 4.2 三级验收

| 级别 | 含义 | 通过条件 |
|---|---|---|
| L1 设置 | Figma 中有 `layoutMode`、spacing、padding、align | 属性写入成功 |
| L2 引擎参与 | 子项不再全部 `ABSOLUTE`，由排版引擎按流摆放 | 静态外观仍通过 |
| L3 行为正确 | 内容增高、长标题、宽度变化时，重排符合预期 | 扰动测试通过 |

V1.1.0 现状：L1 已有；L2 未达到（`figma_bridge/code.js` 的 `setAutoLayout` 会把全部子节点设为 `ABSOLUTE` 并复位快照坐标）；L3 未验证。

### 4.3 转换协议

1. 保留固定坐标基线，确保随时可回到逐像素一致版本。
2. 只挑满足静态门的容器，复制到测试副本。
3. 把候选容器的子项从 `ABSOLUTE` 改为在流，显式写 `FIXED / HUG / FILL`。
4. 静态对比：关键矩形 ≤1 CSS px；换行数、内容数量、显示状态一致。
5. 扰动：栏目高度 +40、标题变长、宽度 ±10%。
6. 通过则保留；失败则回退整个候选子树，不反复修补已漂移坐标。
7. 父容器通过后，才考虑子容器，由外到内逐层升级。

### 4.4 单子项与裁剪容器

- 不能只用子项数量判断。
- 单子项但承担居中、内边距、内容适应或对齐槽位职责的容器，可以保留布局（如 `搜索按钮` 1:372）。
- 只有一个绝对大图、只负责裁剪的容器，列为移除冗余 `layoutMode` 的候选（如 `读书网标志` 1:368、`京东图书活动` 1:402）。
- 具体保留/移除规则见 12.4。

### 4.5 固定坐标保底

- 只限制在必要的最小区域。
- 所有位置以所在固定容器为坐标系。
- 记录容器矩形、子项局部矩形、裁剪范围、锚点/变换和保留原因。
- 只把装饰和叠放子项排除在流外；不把主体文字偷偷改成绝对定位来掩盖布局错误。
- 有旋转/嵌套缩放时做变换矩阵换算，不能只做坐标相减。

## 5. 文本与字体规范

### 5.1 必记字段

- 声明字体栈 `font-family`。
- 浏览器实际解析到的字体/字形回退。
- 字体在 Figma 环境是否可用。
- `font-size`、`font-weight`、`letter-spacing`。
- `line-height` 原始值及其类型：computed px、百分比、`normal`、推断值。
- `text-align`、`white-space`、`text-overflow`、最大行数。
- 文本盒、基线、换行数、可见字形。

### 5.2 行高来源

- `lineHeightSource=computed`：浏览器 computed style 直接给出，优先使用。
- `lineHeightSource=measured`：`normal` 时通过实测行盒/字体度量得到。
- `lineHeightSource=inferred`：缺失时按 1.4em 估算，必须显式标记。
- `lineHeightSource=unknown`：无法确定，保留并报告，不静默套值。

### 5.3 验收

- 文本盒边界一致，不代表基线一致。
- 基线一致，不代表字形一致。
- 字形一致，不代表换行策略一致。
- 三项分别报告；具体阈值与 `normal` 策略见 12.8、13.1.6；可靠测量实验仍待做。

## 6. 图片与矢量资源规范

### 6.1 优先级

1. 同状态的原始资源，图标优先准确矢量。
2. 匹配显示状态的其他合法可访问原资源。
3. 从权威截图按素材边界裁取独立图片。
4. 必要时共享全页图裁剪，并标记来源。
5. 简单 UI 用原生形状/准确图标重建。
6. 复杂封面和品牌图不随意重画或用相似图片替代。
7. 素材仍不可得时，保留参考中的真实占位状态或明确标为缺失。

### 6.2 资产清单

每个资产至少记录：

- 来源（URL / 截图 / 原生重建）。
- 原始尺寸。
- 渲染矩形。
- `object-fit` / `object-position`。
- 裁剪矩形。
- DPR / 缩放。
- 显示状态（正常 / 占位 / 失败 / 懒加载未触发）。
- 是否可独立替换。
- 是否共享（`assetMode=shared-page-crop` 等）。
- 来源证据与不确定项。

具体字段与复用规则见 12.5。

### 6.3 共享裁剪

- 同一 `imageHash` 多次引用不等于文件大 44 倍；但节点、裁剪与渲染开销增加。
- 共享全页图可以用于“不需要编辑的视觉参考”，但必须显式标记。
- 截图路线保存的是截图中的像素，不等于拿到了原图；不能宣称“已提取独立素材”。
- 导出应导出裁剪窗口，避免直接导出内层大图；裁剪不等于数据脱敏。

### 6.4 背景图 / 渐变 / 伪元素

V1 的 `diagnostics.py` 已统计 `grid / flex_wrap / shadow / gradient / pseudo` 缺口；渐变和伪元素装饰尚未进入 DesignSpec。R2-Q03 已给出“原生优先、无法准确表达时局部栅格化并标记”的规则，详见 12.5；复杂 SVG、滤镜和多层混合规则见 13.1.3，矩阵仍待标定。

## 9. 验收与回退

### 9.1 四项验收

1. **视觉还原**：关键容器和文字框边界误差 ≤1 CSS px；截图缩放比例为 `s` 时为 `s px`；图片保持纵横比；不以平均误差掩盖少量大偏移。
2. **结构语义**：层级、分组、命名支持实际编辑任务；单本书替换、作者行增删不需要搜索整页截图或改其他栏目。
3. **编辑行为**：栏目增高 40 px，下游移动 40 px；标题变长、宽度 ±10% 时重排符合预期；固定高度阻断传播能被识别。
4. **资产可替换性**：单封面替换、源图缺失、占位图加载成功但原封面未加载等场景都能定位和处理。

`R3-EXP-11` 已在 24 个合成样例（标定/验证各 12，6 类 × 2 难度）× 6 个变体上完成四项独立标定：两集均为 288/288 状态匹配、故障目标命中 60/60、跨维误报 0/180、baseline 假报警 0/12。错字只触发 visual `fail`，遮挡只触发 visual `partial`（被遮挡正文为 `unknown`），烘焙合成图只触发 asset `fail` 而 visual `pass`，不传播高度只触发 edit `fail`，结构角色错误只触发 structure `fail`。这些结果只证明判定器在合成差分中的定位能力，不证明真实站点、OCR、Figma 写入或生产验收器。

`R3-EXP-12` 用 1 个合成页面建立 11 个参考、6 个状态签名、7 个 scope-state 组和 4 个拼接场景。轮播帧、滚动、缩放、遮挡与过渡均保持独立状态；同态重复 MAE 0、最小几何 IoU 1.0；异态比较不进入几何误差（0；避免 2 个 naive 假差异）。同态全重叠拼接为 `composite-verified`；缺口、混合帧和 v1/v2 混拼均为 `composite-unknown`；v2 显式取代 v1，v3 保持未决，外部 A/B 为 `external-conflict` 且 winner 为 null。16/16 合同检查通过；`composite-conflict`、真实轮播时序、真实外部来源与截图自动状态识别仍未验证。

### 9.2 测试矩阵

- 固定视口、字体、图片状态下的基线对比。
- 某在流栏目高度 +40。
- 卡片标题变长。
- 容器宽度 ±10%。
- 单本书封面替换。
- 源图缺失。
- 占位图加载成功但原封面未加载。
- grid / flex-wrap / 多列场景。
- 轮播帧、懒加载、sticky header 状态。

### 9.3 回退

- 在副本中转换。
- 转换前保存父子层级、顺序、尺寸、变换、约束、裁剪、文字排版参数。
- 验收不通过优先保留原子树、丢弃候选子树。
- 必须原位恢复时，关闭布局并恢复原层级、局部矩形及相关属性。
- 有旋转/嵌套缩放时做变换矩阵换算。

## 12. R2 已收敛规格（2026-10-18）

> 本节把 `ROUND_02_ANSWERS_FORMATTED.md` 中可直接执行的规则写入方案。仍是规格级结论：没有修改实现，没有执行扰动实验；节点状态只到 `candidate`。

### 12.1 配置与状态

**两套配置**

- `faithful`：保留指定状态的几何、换行与显示结果。
- `adaptive`：允许内容增删、尺寸传播和重排。
- 每个候选、实验、阈值和报告都必须写明 `profile`；不得静默混用。
- `adaptive` 不代表原站响应式规则，必须由用户或规格单独提供变列、换行、增高和截断规则。

**验证状态**

| 状态 | 含义 |
|---|---|
| `candidate` | 有证据候选，未完成目标实验 |
| `verified` | 通过静态与扰动验收 |
| `fixed-retained` | 明确保留固定坐标并记录原因 |
| `unsupported` | 当前能力不支持，拒绝伪装为通过 |

**证据状态**

- `observed`：已观察、已测或已读取。
- `derived`：由已知证据推导。
- `estimated`：估算，必须有方法和理由。
- `unknown`：未知，保留空态，不默认通过。
- `derived/estimated` 不得混入“已测”；`candidate` 不得写成 `verified`。

### 12.3 顺序与网格

- 默认用“每行横向 stack + 纵向列表”，不默认使用单个 Figma grid。
- 单个 grid 只有在编辑能力、序列化和精度验证后才可作等价实现。
- 两层 stack 不会原生跨行重排；增删后重建需标记 `regroup-on-rebuild`。
- 分别保存：
  - `dom_order`：源 DOM 顺序；未知就写 `unknown`。
  - `figma_child_order`：当前 Figma 子节点顺序。
  - `visual_order`：按视觉行/列聚类得到的展示顺序。
- 展示顺序在行/列表层重排，不改变内容身份；记录旧序到新序映射、矩形和行聚类依据。
- 不能由当前 Figma 子项反向证明源 DOM 顺序；也不能套用未经验证的 LTR/TTB 假设。

### 12.4 单子项与裁剪容器

- 分开决定“保留 Frame”和“保留 `layoutMode`”。
- 单子项保留布局的条件是存在明确职责：对齐、贴边、padding、Hug、Fill 槽位或必要的尺寸关系。
- 只有一个绝对大图、只负责裁剪的容器，新建时默认普通 Frame；已有节点列为移除 `layoutMode` 的候选。
- 移除前必须核对容器尺寸、裁剪、图片偏移、外层占位、父级 Hug/Fill 和最小尺寸耦合。
- 子项是 flow 不让父级自动成为 flow；普通 Frame + 固定高度不会自动包住变高的内层 flow。
- 已有稿无法判断时默认保留并标 `unknown`；新建稿不凭空开启 stack。
- 决策字段：`container_key`、`role`、`in_flow_count`、`absolute_count`、`layout_required`、`layout_purpose`、`sizing_dependency`、`clip_required`、`decision`、`evidence`、`confidence`、`verification`、`output_node_ref`。
- `layout_purpose` 至少区分：`arrange / align / padding / content-sizing / clip-only`。

### 12.5 资产与使用实例

**三层模型**

- asset：来源、URL、hash、MIME、原始尺寸、解码/可用状态、采集引用。
- use：来源元素与角色、asset 引用、渲染框、`object-fit/object-position`、变换、透明度、裁剪、输出尺寸、替换契约。
- capture state：`capture_id`、视口、DPR、缩放、滚动、坐标系、加载/占位/缺失状态、证据等级。

CSS 背景另记 `background-size/position/repeat/origin/clip` 和多层顺序，不能一律套 `object-fit`。

**复用规则**

- 同一原资源默认去重，多次使用分别记录窗口。
- 只有需要独立资产、局部脱敏、原图巨大只取小部分，或接收环境不能保留变换时，才优先生成独立派生裁片。
- 派生项记录父资产 hash 与裁剪关系；独立裁片不等于独立内容身份，也不一定更小。

**重建优先级**

- 背景图：原资源 + 正确背景映射优先；复杂重复/混合不支持时局部栅格化。
- CSS 渐变：可准确表达时原生，保留层数、角度/坐标、`stop`、混合方式；否则局部栅格化并标记。
- 伪元素：按渲染对象处理；简单形状原生、文本转文本、图像用原资源；复杂滤镜/混合/边界不明时局部裁片。
- inline SVG：优先矢量；不支持的滤镜、外链、复杂特效保留原来源并局部栅格化。

**可替换性**

- `independent`：可按槽位契约替换。
- `derived`：独立派生图，保留派生契约。
- `reference-only`：只保证当前外观。
- `missing`：目标资源缺失。
- 共享大图裁剪、无法隔离文字与背景的合成区域默认 `reference-only`。

**加载失败**

- `faithful-as-captured`：保留指定状态中真实存在的占位，并记录期望资源、实际占位和原因。
- `stable-loaded`：有限重试加载/解码；仍缺图返回 `partial/missing`。
- 只有获准视觉降级且同状态截图确实包含目标内容时，才允许局部裁片，并记录 `mode_change`。

### 12.6 身份与命名

- `entity_key`：站点命名空间 + 经验证的内容类型/业务 ID。
- `occurrence_key`：页面或栏目语义键 + 来源稳定条目 ID，并关联 `entity_key`。
- `slot_key`：广告、轮播等位置身份，与当前 `entity_key` 分开。
- 图层名用于可读展示；IR 保存身份与证据；sidecar manifest 保存输入键到输出节点及版本映射。
- 节点内附属信息只作可选副本，不是唯一真值。
- 定位证据包括选择器、DOM 路径、`visual_index`、行列坐标，不等于永久身份。
- 标题 hash 只作辅助指纹；标题、序号、DOM 路径、节点 ID 不能单独作永久主键。
- 状态：`verified-id / scoped-slot / weak-match / ambiguous / unknown`；冲突必须报告，后写不得覆盖前项。
- sidecar manifest 必须带 `schema_version`、`capture_id`、输出版本。

### 12.7 参考状态与采集结果

**最低字段**

- 目标/最终 URL、重定向、页面类型、采集 `profile`。
- CSS 视口、DPR、设备/浏览器缩放、截图范围和像素尺寸、滚动位置、浏览器版本。
- 语言、时区、色彩/字体环境、授权会话状态。
- cookie/同意条/模态框、轮播目标帧、动画控制方式。
- 字体加载与实际使用证据、图片/背景加载与解码状态。
- `sticky/fixed` 策略与 full-page 捕获方式。
- 每次尝试的 `attempt_id`、父 attempt、`capture_id`、动作、等待条件、分类信号、预算、结果、失败码和缺口。
- 会话秘密、cookie 值、令牌和带凭据 URL 必须排除或脱敏。

**M0 → S → M1**

- 稳定后先测 `M0`，再截图 `S`，再测 `M1`。
- 三者共享 `capture_id`，记录时间、关键矩形、文本摘要、可见状态、图源/hash/自然尺寸、字体状态、轮播标记和滚动值。
- 关键矩形前后变化起始判据 ≤0.5 CSS px，需样例标定。
- `layout hash` 只作快速筛查，必须附字段列表、坐标系、量化精度和 schema。

**结果与拒收**

- 结果明确区分 `complete / partial / rejected`。
- 持续布局抖动、字体变化、轮播切换、遮挡、图源变化、sticky 不明确、DOM/截图显著不一致时重试或拒收。
- 三态必须用内容锚点、表单/挑战特征、URL/状态等多信号联合；冲突标 `unknown/blocked`。
- 不自动填写凭据、不绕过验证码；明确登录/授权障碍不盲重试。
- 重试起点：首次 + 最多 2 次有理由修复，共 3 次；单次 60 秒、总 180 秒；分段滚动另设步数和时限。

### 12.8 文本与字体

**字段分层**

- 源文本与身份：`text_key`、内容/hash、语言、方向、来源角色、DOM 定位。
- 源字体：声明字体、逐 run 实际字体、可用性、字号、字重、字形样式、可变轴、合成粗/斜体、字距/词距。
- 源排版：`line-height` 声明/computed/used、content-box、padding、可用宽度、`white-space`、断词、对齐、overflow、ellipsis/line-clamp、最大行数。
- 源布局：行范围/矩形、行数、文字框边界、字形可见边界、基线与度量来源。
- 输出：Figma 实际字体、字号/字距/行高、文本框、auto-resize、换行、可见结果。

`resolved_font` 逐 run 保存；拿不到实际 run 标 `unknown`。声明字体、加载完成或可用性检查都不能单独证明实际字形来源。

**`line-height: normal`**

- 保留 `normal`，同时记录实际布局结果和字体度量推算值及方法。
- 相邻行位置差可估计行进距离；Range 矩形不等同 CSS 行盒或基线。
- 单行 `normal` 不能凭一次文本框高度推断精确行高。
- 1.4em 只作显式 low-fidelity 回退，必须记录 `estimated`、方法、理由和待验收状态，不能写成 `measured`。

**四项独立验收**

| 项目 | 起始判据 | 未知处理 |
|---|---|---|
| 文字框边界 | 关键边界偏差 ≤1 CSS px | 无测量则 `unknown` |
| 基线 | 有可靠证据时 ≤0.5 CSS px | 无可靠证据标 `not-evaluated`，不得填 0 |
| 换行 | 未改内容/宽度时行数与换行点一致 | 未测则 `unknown` |
| 可见字形 | 可见边缘 ≤1 CSS px 作几何起点，并核对字形特征 | 未覆盖的字体/平台仍记 `partial/unknown`；Chromium + WebKit 标定见 `R3-EXP-13` |

字形检查覆盖标点、粗细、缺字和省略号。字体相同不保证逐像素相同；截图/画布缩放必须换算。

**字体不可用**

- 保留 `source_declared_font`、`output_font`、`fallback_reason`、受影响范围和验收状态。
- 高 `faithful` 要求先请求字体或明确接受误差；获准替换后按真实替代字体重新排版，不能仍声称原字体。
- 不静默做全页缩放，不以改字号/字距凑宽；必要微调保留原值、改值、原因、逐角色验证和回退方式。

- 网格聚类以垂直重叠、上沿、水平步长和内容角色为主；中心点仅辅助，不能用封面中心代表卡片中心。

#### 13.1.2 grid 与 regroup-on-rebuild

- 2026-10-18 真机实验：独立实验插件在 Figma `126.9.13` 的可编辑文件上完成 27/27 步基础探测、32/32 步补充探测和 13/13 步隔离复测。已实测固定轨道、手动定位、`ROW_AUTO_FLOW`、`ROWS` 自动轨道、`appendChildAt`、行列重排、1D wrap 和保存重开回读。补充结论：跨度本身不拉伸，配合 `FILL` 后跨 2 列为 `170`、跨 2 行为 `130`；`MIN/CENTER/MAX` 在 80×60 固定单元格内分别偏移 `20px`；`FLEX 1/2/1` 为 `60/120/60`；HUG 列与 HUG 父帧把父帧宽度从 `276` 推到 `296`。父帧设为 `HUG` 会把现有 `FLEX` 列改写为 `HUG`，恢复 `FIXED` 后不会自动恢复，必须备份并重写轨道类型。嵌套 grid、直接创建 HUG 轨道并搭配 `FILL` 子项的宽度求解、自动/混合轨道、全页面编辑和生产 bridge 集成仍未覆盖。生产 `figma_bridge/code.js` 仍只设置 H/V，不能把本次实验写成 bridge 已支持 grid/wrap。
- 单个 grid 进入白名单前，逐项确认：行列定义、轨道尺寸、gap/padding、填充顺序、跨行跨列、单元格对齐、子项尺寸策略。
- 几何验证覆盖全部单元格、外边界、空槽和最后一行。
- 编辑验证覆盖增删、换序、长文本、变宽、跨行传播和装饰定位。
- 序列化验证覆盖保存重开与导出回读后的轨道、顺序、尺寸、裁剪和身份映射。
- 白名单必须绑定能力版本、`profile` 与测试范围；单样例通过不代表所有 grid 通过。
- 视觉几何相同可以允许层数不同；但合同要求原生重排时，固定坐标和仅重建时重组都不等价。
- `adaptive` 选择顺序：需要严格二维轨道对齐用已验证 grid；一维按宽度包行用已验证 wrap；只在重建时调整用重组策略。
- 当前能力不可用时，对“原生换行”标 `unsupported`，不能改名冒充。
- `regroup-on-rebuild` 记录旧/新出现键、旧/新行列、旧/新显示索引、旧节点引用、来源矩形、聚类方法与容差、列数与分行策略、输入/输出版本、变更原因、插入/删除/移动/未匹配项。
- 行 wrapper 可随重分组换身份；卡片身份不因行号改变。
- 空槽与最后一行至少区分 `compact` 与 `preserve-slots`；最后一行不得临时 Fill 撑宽；可约定固定卡宽、靠起始边、不补造卡片、显式记录 `empty-slot`。
- 无明确规则时可以保留静态几何，但增删与重排能力标 `unsupported / blocked`，不把整页一律判废。

#### 13.1.3 复杂效果与资产边界

- 每个效果项至少记录 `native-candidate`、`raster-fallback` 或 `unsupported`，并附依赖条件、版本和证据。
- 原生可表达不等于本实现已正确实现；名字相同、SVG 导入成功都不构成等价证明。
- 单算子通过不证明效果链通过；实验需覆盖透明背景、多层叠放、裁剪和组合效果，并比较外扩、颜色与遮挡区域。
- CSS 渐变只有在色标、坐标、裁剪和色彩处理可对应时才作原生候选，否则局部栅格化并记录映射。
- 简单阴影、blur、drop-shadow 与混合模式只作条件候选，不默认 CSS 与目标渲染器数值一一对应。
- 复杂 `mask-composite`、luminance、`clip-path` 及未验证的 filter/foreignObject/外部引用/动画，局部栅格化或 `blocked`。
- 伪元素承载可见文字、参与排列、提供编号或关键状态、遮挡影响阅读时，升级为独立渲染或语义对象并关联 owner。
- `reference-only` 最低记录来源与 capture、原始片段及依赖、效果链与叠放、边界/裁剪/变换、栅格化范围、被合并文字、不可编辑部分、替换所需资源与条件、未支持特性和验收结果。
- `faithful` 先满足误差门槛，再比较编辑性；`adaptive` 要求效果参数可编辑时，裁片不能算原生效果通过。

#### 13.1.4 身份与出现匹配

- 先按已确认页面与栏目范围限制候选，再参考可靠内容关联、文字与图片联合指纹、稳定角色锚点与邻域；矩形距离和视觉序号只作弱辅助。
- 采用有冲突检测的一对一匹配，不逐条最近邻。
- 记录特征、特征缺失、匹配成本、候选差距与接受阈值；权重和阈值必须由样例标定，不输出伪精确分数。
- 唯一且证据充分时保留 `occurrence_key`；仅有推测时输出 `proposed-match`。
- 插队、删除、换序不自动改变已有身份；新出现项新建键，确认删除项保留历史。
- 采集不完整或虚拟列表未遍历时只记 `not-seen`，不得认定 `deleted`。
- 同实体同栏目重复只有在稳定业务槽、不同来源上下文/关系或持久来源锚点存在时才稳定区分；完全相同的副本互换必须保留歧义。
- 虚拟列表记录数据游标、绝对列表位置及来源、分段 capture、可见窗口、节点复用和覆盖范围；`entity` 与 `occurrence` 分开。
- 多对一、一对多、同分候选、跨栏目归属不明、内容大幅变化、重要对象可能误替换、弱证据与可靠业务身份冲突时，停止自动匹配并转人工确认。
- `weak-match` 只报告低把握关联，不自动用于破坏性更新。

#### 13.1.5 full-page 与 sticky 同态

- 参考分三类：单视口状态、保持原视口的文档捕获、逐段合成参考。
- 分块拼接与扩展视口默认不等同；只有布局、媒体条件、视口单位、sticky/fixed 和加载状态经证据证明等价时，才在该范围比较。
- 拼接参考的每段记录 `capture_id`、`segment_id`、时间、视口、滚动、裁剪/拼接变换、重叠区、字体/资源/状态，并逐段做 M0／S／M1。
- 全局参考标 `composite`；不得伪称浏览器曾同时显示整张长图。
- sticky/fixed 每段对应同一滚动状态；固定头“只保留一次 / 重复出现 / 被隐去”必须显式记录。
- 比较信号至少包括实际视口与媒体条件、视口单位区域尺寸、fixed 背景相位与定位、sticky 锚点、图源与自然尺寸、重叠区匹配、段间文本/对象身份、累计拼接变换。
- 0.5 CSS px 只作约定坐标系下局部关键矩形的起始门槛，不用于拼接误差、字形误差或全页所有区域。
- 长页分层覆盖页头、页尾、全部接缝、sticky、懒加载边界与重复区域，并报告采样覆盖；未采样区域不得算通过。
- 部分同态报告有效区域、无效/未知区域、各段参考与原因；有效区只支持局部几何，不得推断跨接缝 gap、全页总高、全局顺序或跨状态尺寸传播。
- 核心布局依赖上述关系时转换标 `blocked`，不能拿 `partial` 支持整页 `verified`。
- 2026-10-18 受控实验：Playwright 1.62.0 / Chromium 151.0.7922.34、1200×800、DPR 1 的本地页完成 8 段原视口拼接、保持原视口的 `full_page=True` 文档捕获和 4904 高扩展视口捕获。8 段 M0/M1 全部稳定，覆盖 `[0,4904]` 无缺口；屏蔽 sticky/fixed 区域后，拼接与文档捕获在 86.7961% 有效像素上的平均差、P99、最大值均为 0。扩展视口把 hero 从 800 改为 4904、`docHeight` 从 4904 改为 9008，截图只覆盖 54.44%；懒加载把 `docHeight` 从 4504 推到 4904。该结果只证明方法与失败模式，真实站点、跨浏览器、动态状态与跨接缝资源变化仍需各自证据。

#### 13.1.6 `normal`、基线与字形阈值

- 保留 `normal` 声明，交叉参考容器矩形、文本 Range 矩形、相邻行进距离、实际字体 run 与字体度量。
- Range 是片段矩形，不等同准确行盒；字体或 Canvas 度量不能单独代表 CSS 行高。
- 基线探针只作受控实验：使用零尺寸、基线对齐的内联探针辅助定位 alphabetic baseline，并验证不改变行高、换行与布局，之后恢复原内容。
- 中文基线必须写明 alphabetic、ideographic 或其他定义；可见字形底边不是基线。
- 多行逐行记录；混合 run 区分行基线与 run 偏移；上标、下标和不同字体不能只用一个整段值。
- 无可靠源或输出基线时，基线偏差、逐 run 垂直对齐和由基线推导的精确行盒结论均标 `not-evaluated`，不得补成误差 0；内容、换行、可见字形和边界仍可独立检查。
- 阈值标定固定字体二进制/版本/可变轴、字号、字重、DPR、浏览器版本、输出渲染版本与色彩条件。
- 字符集至少覆盖常见中文、全角标点、拉丁大小写、数字、中英混排、省略号、粗斜体、缺字；emoji 另测。
- 先估同环境重复捕获噪声，再比较跨渲染器分布；分角色报告边缘、行进、换行与粗细差异。
- 2026-10-18 受控实验：Chromium 151.0.7922.34、1200×1600、24px/32px、DPR 1/2 的本地页完成 12 个用例。Arial 实际行进 32，YaHei/混排 33，`line-height:32px` 不等于实际行进；零尺寸基线探针不改变容器、滚动高度、客户端高度或非零行盒，移除后布局完全一致；混排 YaHei 顶部 585 + ascent 25 与 Arial 顶部 588 + ascent 22 同为基线 610。3 次重复 CSS 度量一致，DPR 1/2 CSS 度量一致；`document.fonts.check` 对缺字仍返回 true，截图为两个 tofu。`R3-EXP-13` 已补 Chromium + WebKit（基线最大差 0.5px）；Firefox、其他版本/操作系统与通用阈值仍为 `not-evaluated`。
- 字体不可用且未获准替换时输出 `blocked-font / partial`，保留文本内容、原始字体声明、矩形和证据；已有原生文本可保留但标未验收。
- 只有提供字体或获准替代后，才生成可编辑草稿并标 `draft / fallback`，不得用隐式替换伪装 1:1。

### 13.2 截图主线

#### 13.2.1 reference 与坐标

- 上传截图原像素尺寸为 2544×4959；本轮没有可靠 DPR、CSS 视口或实际字体声明，URL 截图的视口信息不得移植。
- 最低输入记录 `reference_id`、来源与授权、内容 hash、格式、原像素宽高、当前缩放/裁切/变换、单屏/全页/拼接/未知、已知时间、参考范围与 `profile`。
- DPR、CSS 视口、浏览器缩放、滚动、语言/字体、轮播/占位/遮挡、浏览器外观已知则记，未知则 `unknown`；明确解码后的方向。
- 单图只支持可见范围与该显示状态的 `faithful` 结论；同态多图需一致内容、尺度和状态证据；不同状态分别建立 reference/state。
- 元信息缺失时以源图像素坐标重建；均匀缩放定义 `canvas = s × source + offset`，不凭图片宽度反推 CSS 视口或 DPR；CSS 尺度未知时不报 CSS px。
- 地址栏与系统外框属截图外观层；滚动条来源不明标 `unknown`；网页弹窗、cookie 条与遮罩作为 overlay 保留，不占常规 flow。
- 默认 `faithful`；`adaptive` 只能提出候选，变列、增高、截断和编辑范围须由用户明确给定或经确认的方案提供。
- 拼接长图记录每段 hash、顺序、像素范围、重叠/接缝、缩放/裁切、已知滚动/时间、重复 fixed 区域、状态差异与内容缺口；来源未知标 `composite-unknown`。

#### 13.2.2 分组与 IR

- 先划页面、overlay 与截图外观范围，再综合标题/内容关系、共同背景与边界、留白/对齐、重复模式；不设单一视觉信号的绝对优先级。
- 明确栏目标题与内容关联通常强于单纯视觉接近；跨区域共享白底不是合组证据。
- 独立栏目候选需要明确作用域和相互独立的支持，例如“标题关联＋内容集合”或“共同边界＋内部一致排列”。
- 重复卡片候选需要角色组合重复、视觉模式重复和可解释内容边界；两个近似矩形不足以确认卡片语义。
- “两种证据”只是审查起点，不是自动正确的数学门槛。
- 采用页面区域、栏目、布局行列、卡片、元素层级，但不强制固定树深；侧栏与主栏可在同一布局行而保持独立栏目身份；页脚不与上一组排行合并；弹窗独立 overlay；焦点与导航分开。
- 语义不明时保留最小 `unknown` 区域，不为凑树强合并，也不把每个像素块拆成语义对象。
- 单子项、裁剪窗口与装饰的用途和替代解释分别记录；“看起来居中”不证明 Hug／Fill。
- IR 分别记录 `object_id`、`role`、`parent_relation`、`pixel_region`、`boundary_evidence`、`semantic_evidence`、`alternatives`、`evidence_status`、`review_status`。
- 重新分组可改变父关系版本，不重建全部对象身份；拆分、合并保留 lineage；检测框是估计区域，不是 CSS 容器边界。

#### 13.2.3 截图文本与 OCR

- 原生文本准入最低记录来源区域、可见字符候选、阅读方向/行序、未识别片段和内容核对状态。
- OCR 分数保留原始口径，不当作跨语言、跨识别方式通用的真实概率；高分不能覆盖画面冲突。
- 金额、日期、姓名、编号等证据性内容从严复核；低清或冲突项不自动定稿。
- `faithful` 先保持可见行序与断行；能可靠重建同一段落和断行时优先原生段落，否则用显式换行、逐行文本或 `line-preserved` 标记。
- 逐行层可编辑不代表段落可重排；`adaptive` 另行定义段落边界与换行规则。
- 中英、数字、标点逐项核对；可见省略号只保留可见内容，不扩写被截断标题。
- 字体参数不唯一时记录 OCR 原文/修订文、候选字符、可获得范围、来源框、字体候选与依据、字号/字重/行高/字距估计、输出值和替代状态。
- 明确允许近似时可用已声明字体制作草稿，但不能标精确复刻；缺失字体的替换须获准。
- 导航、正文、书名、作者等普通 UI 文字目标为原生文本；品牌字标和艺术字可作素材；没有原始矢量时轮廓化不算可编辑文字。
- 无法辨认时保留证据像素，候选转写只放报告，不用猜测覆盖原图。
- 不按 OCR 候选、常识或上下文补全不可见文字；遮挡/压缩/模糊片段标 `unknown` 并附区域与候选；用户确认补文标 `user-supplied`。
- CSS 尺度未知时以源图像素计；文本框称“可见文字区域”或“重建框”，不假称原 CSS 盒；基线缺失标 `not-evaluated`。
- 抗锯齿、压缩与缩放需重新标定；内容与换行独立核对，不能靠字形相似掩盖错字。
- `R3-EXP-08` 的受控结果只支持“双引擎候选 + 人工复核”，不支持单引擎置信度自动接受：Tesseract 与 EasyOCR 在 mean_conf ≥ 0.8 的接受项中分别有 128 与 36 条错误；逐 token 原始置信度只能用于排序和复核优先级。
- 字号、JPEG 质量与模糊均无统一单调阈值：32px 普通文本仍只有 5/7 或 3/7 核心 exact；JPEG q90 与 q15 的 exact 同为 4/13，q50/q30 为 3/13；EasyOCR 在模糊 σ2.0 降到 0/7。阈值必须按用例、内容和版面条件标定。
- 金额、日期、编号等证据字段必须严格 exact；清晰 32px 下 EasyOCR 仍可能把 `¥` 识别为 `半`。遮挡内容保持 `unknown`，用户补文只记 `user-supplied-unverified`。
- 断行、文本框和内容分别验收：行数匹配不代表断行正确（447 条记录行数匹配但核心字符错误）；文本框 IoU 也不代表内容正确（exact 与错误记录的 IoU 中位数分别为 0.803 与 0.819）。字形可分性只在当前字体/渲染器内标定。

#### 13.2.4 截图资产

- 独立裁片候选需可隔离可见边界、足够分辨率、无必须保留的外部内容叠入、明确替换槽位；重复出现只辅助确认，不能恢复缺失像素。
- 扁平截图一般不证明透明通道，与底色相同的区域不得当作真实透明。
- 书封内印刷文字属素材；封面外标题、作者属 UI 文本；图标抗锯齿带底色、阴影落纹理、文字盖照片、复杂透明叠放难以隔离时保留 `reference-only` 合成区域。
- 重画或去背景改变证据，需另行授权并标改作，不自动声称还原原素材。
- 相同裁片像素 hash 相同可去重；尺寸/裁切不同且仅视觉相似不能证明同一原图；保留派生裁片与 `same-source` 候选关系。
- 优先策略：简单形状/圆角/边框/分隔线优先原生；准确已知矢量或简单几何图标优先；logo/艺术字保留证据素材；渐变/阴影参数属推断，验证达标才原生；纹理/照片/书封保留栅格。
- `provenance` 记录原资源、截图裁片、共享裁剪、原生重建；`replaceability` 记录 `independent / constrained / reference-only / missing`。
- 兼容旧 `derived` 字段时必须附替换能力；逐项报告来源、边界、分辨率、合并内容、替换范围与限制。
- 来源可追溯、可导出、可独立替换、素材内部可编辑是四项不同能力，分别报告。
- `R3-EXP-09` 在 9 个受控资产上验证了分离方式：4 个封面用途与干净照片为 `independent`，文字盖图与阴影图标为 `reference-only`，低清 logo 与原生徽章为 `constrained`；标签 9/9，但原因只有 8/9，`flat_badge` 的像素原因不等于其内部可编辑性。不得把该结果写成通用分类器已验证。
- 所有观测来源都只到 `page-screenshot-crop`，`traceable=partial`。精确重复只能支撑 `exact-duplicate-group`；同源候选不能恢复原文件，`derived` 也不能自动获得独立替换能力。
- 共享整页图与独立裁片没有单调成本优势：本页 1x PNG 共享更小，1x JPEG 与 2x PNG/JPEG 独立裁片更小；9 次替换中共享整页耗时约为独立的 4.0–7.0 倍、字节约为 3.4–5.3 倍。选择模式必须按页面、格式与替换次数实测。
- 矩形替换的碰撞必须单独报告：独立资产为 0–0.0005，合成/受限资产为 0.0264–0.6649；有碰撞时不能把该区域当作可独立替换。
- 像素差 mask 对与底色相同的内容不可见（白色 logo 图形、徽章白字会被记成封闭孔洞）；孔洞必须与非目标方差联合判断，不能单独作为 baked overlay 证据。

#### 13.2.5 截图 flow

- flow `candidate` 最低要求：可解释的顺序与主轴、明确作用域、重复角色、间隔/对齐证据、尺寸策略可闭合、重叠可独立解释、文字与素材几何足够稳定。
- 单子项对齐可进入候选，但不能只凭视觉居中推断原 Hug／Fill；证据不足保留固定区域或 `pending-evidence`。
- 无扰动实验不得标 `verified`；L1 已设置、L2 布局确实参与、L3 在声明测试范围内行为正确，分别记录。
- 即使 L3 通过也只证明本次输出，不证明网页原规则；建议字段 `verified_for=output-contract`、`source_behavior=inferred`。
- `faithful` 可内部重组或采用 flow，但指定状态外观与内容不变，不引入新断行、隐藏项或未获准响应式假设。
- `adaptive` 的变列、增高、截断、最小宽度等由用户给定或确认方案提供，并记录 `accepted-by` 与版本。
- 区域策略：页面纵向；卡片集合行横向＋列表纵向；卡片信息纵向；页头按真实视觉子区拆分；主栏/侧栏同一横向区域、各自内部纵向；页脚按内容行组织。
- 尺寸默认忠实于证据，Fill／Hug 不是默认；两层 stack 跨行重组仍需显式规则。
- 复杂叠放、疑似拼接、装饰不可分离、文本不可靠、多个同样合理排列、转换后几何超阈值时保留固定坐标。
- 错序、丢项、非预期遮挡、传播不符、装饰脱锚时回退该区域；允许“父 flow＋子固定”但披露限制。
- 与 DOM 冲突时截图轨只记 `external-conflict` 与对应 reference，不用 DOM 覆盖截图证据；R4 前保持来源隔离。
- `R3-EXP-10` 的 7 个合成输出场景已验证：页面纵向 stack 在 `+40`、插入/删除与宽度 `+10%` 下传播正确；卡片信息 `237→281→299`；页脚第 2 行 `44→84`、页脚 `222→262`；绝对分隔线 `y 43→83`。宽度缩小导致固定卡片溢出 68.4 时回退整个区域为固定坐标；主栏/侧栏溢出 19 时保留静态宽度并标 `partial-fixed-width`；复杂叠放保持 `NONE`。
- `R3-EXP-10` 的首轮 HUG 被后续 `resize()` 覆盖、页脚行 `AUTO/FIXED` 声明矛盾与 768/764 预期错误均已披露并修复；通过项只写 `verified_for=output-contract`、`source_behavior=inferred`。

#### 13.2.6 四项验收与报告

- 四项分别记录对象/范围、要求、证据、指标/单位、阈值来源、实际结果、覆盖、未测项、状态、原因与修复建议。
- 视觉检查几何、内容、字形与像素；结构语义检查角色与边界；编辑行为检查原生文本与布局扰动；资产检查替换合同。
- 缩放定义 `s = 画布长度 ÷ 源图像素长度`；均匀缩放时 `画布阈值 = s × 源图阈值`、`源图误差 = 画布误差 ÷ s`；CSS 尺度未知不报 CSS px。
- 源图 1 px 只是起始几何容差，不豁免压缩/插值误差；非均匀变换分别记录，不套单个 `s`；配准只用声明变换，不局部拉伸隐藏错位。
- 状态含义：`pass` 为声明范围内全部满足；`partial` 为有已验证可用子集且缺口明确；`fail` 为要求与结果明确矛盾；`unknown` 为证据不足或未测。
- 视觉像但结构错可以视觉 `pass`、结构 `fail`；要求原生正文却是图片则编辑 `fail`；要求独立替换但只有 `reference-only` 则资产 `fail` 或局部 `partial`。
- 文本误差分内容转写、可见断行、字体替换、文字区域、基线、字形；可汇总问题数但保留子项；基线未测是 `unknown` 不是 0。
- 四项必须有独立证据链：内容用严格 exact 与核心字符，断行用内容门控后的行数与行序，文本框只证明框估计，字形用局部可分性表；OCR 置信度、单一 IoU、行数匹配都不能覆盖其他维度。
- 资产验收的独立证据链为：来源（截图裁片/重复组/合成窗口，保持 `partial`）、可导出（PNG/JPEG 字节）、可独立替换（纯度/边界/低清与合成判定）、内部可编辑（扁平截图保持 `not-observable-from-flat-crop`）。`R3-EXP-09` 的 9/9 标签一致不能替代“原因一致”；`flat_badge` 已给出标签巧合的反例。
- 资产报告需同时附同源候选（分数、尺度、方向）、精确重复、共享/独立/去重/混合模式的字节与替换成本，以及矩形替换碰撞的两个分母（占窗口、占非目标像素）。碰撞超过独立容差时，该资产不能报为可独立替换。
- 只有关键目标仍存在可用范围、缺口可隔离且不误导使用时，整体 `partial` 才成立；核心正文错误、关键资产不可替换、状态整体不可用不能用其他区域平均掉失败。
- `partial` 附有效/不可用区域、缺口清单、证据等级、影响、不可做的编辑、人工复核项、建议动作、是否满足最低目标；不编造概率。
- 固定样例集覆盖中文、英文、混排、图标与 logo、复杂背景、长页，每类含清晰与困难输入，四项分别打标；保留独立标定集与验收集。
- 评分分母必须说明是页面、区域、对象、字符还是被测用例；未覆盖部分不进通过分子。
- `R3-EXP-11` 的冻结阈值为：`content_object_exact_min=0.98`、`content_character_exact_min=0.999`、`linebreak_match_min=1.0`、`glyph_local_mae_max=4.0`、`pixel_card_mae_max=0.1`、`geometry_min_iou_min=0.999`、`structure_role_accuracy_min=0.98`、`structure_parent_accuracy_min=0.999`、`structure_boundary_min_iou_min=0.999`、`edit_native_text_ratio_min=1.0`、`edit_propagation_error_px_max=16.0`、`asset_layer_isolation_min=0.5`、`asset_corner_unchanged_min=0.5`、`change_region_ratio_min=0.02`。其中断行、像素、几何、父关系、边界、原生文本没有对应故障变体，只能作为合同值或干净噪声边界，不能写成已标定判别阈值。

#### 13.4.1 交付级别

交付级别由四项状态推导，不替代四项分别报告：

| 级别 | 条件 | 可以说 | 不能说 |
|---|---|---|---|

#### 13.4.2 关键项与非关键项

- 关键项：文字内容、主图或关键素材、布局顺序、按钮与主要控件位置、主要尺寸关系。
- 非关键项：阴影、渐变、抗锯齿、轻微色差、非关键圆角与装饰。
- 关键项出现 `fail` 时，不能靠非关键项或整体视觉相似提升为交付级。
- 证据不足的关键项保留 `unknown`，不得默认通过。

#### 13.4.3 字体缺失

- 默认输出 `blocked-font / partial`，保留文字内容、原字体声明、矩形和证据。
- 用户授权替换后，记录原字体、替代字体、替换范围和换行变化；输出标 `draft / fallback`。
- 品牌字标、艺术字优先保留为素材，不强行做可编辑文字。
- 替换字体后必须重新检查断行、溢出和关键文字区域，不能只凭“看起来接近”通过。

#### 13.4.4 部分交付

- 必须同时提供：有效区、无效区或遮挡掩码、缺口清单、影响、不可做的编辑、人工复核项、是否满足最低目标。

R4-EXP-01–R4-EXP-10 的准入规则：

1. 融合前必须先过 scope/state 门；异态、瞬态和遮挡状态不得进入字段比较。
2. 字段权威固定：`text / font / color / role / editability / asset_source` → DOM；`visible_state / occlusion / z_order / rendered_effect` → 截图；`content_hash / pairing` → 交叉核对。
3. bbox 只用绝对容差；超差返回 `external-conflict`，禁止平均或多数投票。
4. 每个结果必须有 `status`、`reason` 与 provenance；未决态保留双侧观测且 `winner=null`。
5. 截图裁片只能标 `flat-raster-crop`，不得宣称原始资产、原生可编辑或 DOM 身份。
6. `screenshot-candidate` 的文本与可编辑性保持 `unverified`。
7. 本实验的截图观测值是附着在真实截图上的夹具输入，`derived_from_pixels=false`；不得把结果写成 OCR/CV 准确率。
8. 仍未进入生产白名单；`src/`、`figma_bridge/` 未修改，未执行 Figma 写入。
9. OCR 候选必须保留引擎、版本、原始/规范化文本、置信度、裁片框与页面框，并标 `verified=false`；OCR 只在给定框内运行，不是端到端检测。
10. 遮挡门先于文本比较与置信度门；高置信度不得覆盖遮挡。单引擎、双引擎分歧、重复文本和几何未对齐都不得自动升级文本内容。
11. 只有双引擎 exact、置信度与几何同时过门时才允许提升 `text-content`；`editability / role / asset_source` 永不随 OCR/CV 升级。
12. CV 轮廓框只能作 `visual-box-candidate`，不得推断语义角色、可编辑性或原始资产；高 IoU 不是语义证据。
13. `0.85 / 0.50 / 0.30` 是 R4-EXP-02 的实验合同值，不是通用阈值；升级精度 2/2 不代表真实站点接受率。
14. `unknown` 分支在 R4-EXP-02 中未被真实触发，不能写成已覆盖；真实站点、跨 DPR、跨语言和多引擎矩阵仍待验证。
15. 状态门必须先于字段和像素比较；异态对不比较、不平均、不修补。R4-EXP-03 的 51 个被阻断对若直接比较会产生 2172 个状态导致的假差异。
16. 状态签名至少应包含滚动位置、内容代次、文档高度、动画相位、pending 标记与滚动进行中标记，并记录视口；本实验未做逐字段消融，不能把这些字段写成最小必要集合。
17. 截图前后状态不一致，或存在 pending 懒加载、滚动进行中标记时，捕获必须标为 transient；R4-EXP-03 中相关 19 个唯一捕获对全部不得进入比较。
18. 只有同态重复才允许比较；同态重复应共享状态哈希，并在稳定捕获上得到零字段差异与零缩略图像素差。像素检查只是同态一致性佐证，不是通用视觉回归阈值。
19. sticky 元素必须同时记录视口 bbox 与文档 bbox；R4-EXP-03 中视口框保持 `[0, 0, 1200, 64]`，文档顶部却从 0 变为 900。
20. 懒加载代次与文档高度变化属于状态迁移；本实验探针数 23 → 26 → 29 → 32、文档高度 3112 → 3032，不能当作元素缺失或布局缺陷。
21. 动画相位不同即不可比较；`S00_top vs S03_anim700` 仅因 `animation-phase` 阻断。本实验是暂停相位，不是实时动画采样。
22. R4-EXP-03 的 `1.0 px / 16 ms / 0.05 / 0.02 / 0.00005` 均为实验合同值，不是通用几何、动画或视觉回归阈值；真实站点与跨浏览器状态仍未覆盖。
23. IR 必须显式版本化并带 `schema_hash` 与 `content_hash`；每个字段至少记录 `authority / status / selected / selected_source / reason / provenance / retained_observations`。
24. 冲突字段必须保留双侧观测且 `selected=null`；`unknown` 必须保留 `present=false, value=null` 的 absent observation，不得发明值。
25. OCR 只允许提升 `text-content`；`editability / role / asset_source` 永不从 OCR/CV 候选升级，且必须作为显式边界字段记录。
26. 被阻断的状态对不得携带 `field_result`；与瞬态捕获相关的状态对不得进入字段或像素比较。
27. R4-EXP-04 的 22/22 检查只证明三个来源实验之间的合同自洽与非法变异拒绝，不是生产 schema、持久化实现或外部真值验证。
28. bbox 容差只在同 scope、同状态签名、唯一配对之后生效；2.0 px 不能替代状态门、身份门或缺值判断。
29. DOM 与截图 bbox 必须在同一 CSS px 坐标系比较，截图物理框按 DPR 归一；规则为 `max(|Δleft|,|Δtop|,|Δright|,|Δbottom|) <= 2.0 px`，超差保持 `external-conflict` 且禁止平均。
30. R4-EXP-05 的 200/200 只覆盖 Chromium、纯色背景连通域与 CSS zoom；不能把 `2.0 px` 写成跨浏览器、跨平台或跨字体的通用阈值。
31. 截图 bbox 的产生口径必须显式记录；连通域可见足迹不是 OCR/CV 检测框，不能据此宣称检测精度或漏检率。
32. 8 px 徽标与 1.25 px 细线的通过不能推广到任意极小字形、图标或亚像素线；变换、裁剪、遮挡、半透明、阴影与图片资产仍未覆盖。
33. 配对必须先判内容主特征与完全相同副本平局，再进入位置、顺序、邻接与一对一分配；`primary-content-tie` 不得被坐标、遍历顺序或节点 ID 打破。
34. 节点 ID 只可作调试字段，不得进入身份特征或用于强配；R4-EXP-06 的节点 ID 基线在 12 个场景中产生 3 个错误配对、8 条错误记录，随机替换节点 ID 后结果不变。
35. 采集范围必须显式记录；范围外旧项输出 `not-seen`，不得写成 `deleted`。R4-EXP-06 的 6 个 `not-seen` 全部来自局部采集或未重新出现，输出中没有 `deleted`。
36. 配对必须保持一对一，并输出 `proposed-match / ambiguous / not-seen` 与 `matched / ambiguous / unmatched-new`；`accept=0.20 / gap=0.04 / coverage>=0.30` 只是本次 12 个受控场景的弱标定，零错误交集 `accept 0.20–0.25 × gap 0.02–0.06` 不能写成通用阈值。
37. R4-EXP-06 的 46/46 只覆盖受控合成页面、DPR 1 与 8×8 RGB 截图签名；不得写成真实站点配对准确率、感知哈希、OCR/CV 检测或生产匹配 API。
38. 资产来源必须先区分原生/本地来源、通过验证的 HTTP 原图与光栅降级；`inline-svg / native-css / data-uri / blob-url` 不得被无条件转换成位图，截图与 canvas 导出只能标 `flat-raster-crop`。
39. HTTP 原图必须同时通过状态 200、非空正文、MIME 嗅探、header/body 一致、完整解码与预期尺寸门；失败原因必须保留为 `http-404 / timeout / mime-body-mismatch / decode-failed`，不得合并成单一下载失败。
40. 跨域资产不能只靠页面上下文 `fetch` 判断可用性；懒加载资产未触发时应输出未加载状态，而不是 `missing`。R4-EXP-07 只证明所测 loopback 场景，不构成通用跨域或懒加载策略。
41. 元素截图是固定成本；R4-EXP-07 的 20 次裁片 P50 约 64.05 ms。生产应只在原图不可用时按需生成，不得把实验中的全量裁片成本当作默认路径。
42. R4-EXP-07 的 20/20 与 39/39 只覆盖受控 loopback 页面、Chromium 与 DPR 1/2；不得写成真实站点资产接受率、下载成功率、生产覆盖率或 Figma 资产替换能力。

44. `supersedes` 必须同页面家族、目标存在、来源有授权且轮次严格递增；结构图先检环，再判单调性。环存在时整条链输出 `invalid-authority-chain`，不得返回部分 winner。
45. 显式墓碑才表示删除；缺失字段只能输出 `not-seen` 或 `carried-forward-not-seen`。单一外部候选为 `authority-required`，多个不同候选为 `external-conflict`，后者 winner 必须为 `null`。
46. 写入前必须先产出字段级决策；只有 `written` 才可生成 bridge 命令，`deferred` / `skipped` 必须零命令，不能静默缺省或写入占位值。
47. 文本写入只接受 DOM 选中值或显式上游双引擎 exact 晋升值；单引擎、冲突、歧义、未观测和遮挡文本不得写。OCR 门槛沿用 `0.85 / 0.50 / 0.30` 实验合同值。
48. 颜色写入只接受选中的 DOM provenance；截图-only 颜色只能作为未选观测保留，不得升格为可写颜色。
49. 资产命令必须携带 claim；已验证 HTTP 原图可写，截图裁片只能以 `flat-raster-crop` 写入并保留 `cannot_claim`，未验证资产与无写实现的 native 来源零命令。
50. 完全遮挡节点为 `skipped`、遮挡未知节点为 `deferred`；写入顺序按截图 `z_order` 升序，不按 DOM 顺序。若 bridge 无 `visible` / 隐藏能力，必须不写或显式延迟，不能伪造 `visible=false`。
51. 写入执行前必须校验 bridge action 白名单、必填参数、图像 base64 解码与 SHA-256；任何校验失败只阻断该命令，不退回默认值。
52. R4-EXP-09 的 38/38 与 8/8 只证明受控夹具上的决策合同与 mock executor 安全回放；`real_figma_connected=false`、`figma_write=false`、`source_mutation=false`，不得写成 Figma 写入成功、插件兼容率或生产事务验证。
53. R4-EXP-10 的 stage bundle 只用于产物级审计；`sequence_semantics=ordered-audit-only`，不得把实验顺序写成运行时数据依赖。
54. 每个阶段必须有状态、scope、summary、checks 与 canonical digest；缺显式 `content_hash` 时可用派生 digest，但必须标 `stored-content-hash-not-declared`，不得当作写盘 attestation。
55. 缺 boundary 或 limitations 必须保留为 envelope gap，不得用缺省值补成已证明。当前 R4 九阶段已全部声明 boundary 与 limitations（`envelope_gaps={}`）；补齐记录见 `r4_metadata_supplement.json`。
56. 聚合前必须验证所有阶段检查；任一阶段检查失败、状态非 `completed-for-current-scope`、boundary 出现 `figma_write` / `real_figma_connected` / `source_mutation`，或阶段重复时，整个 bundle 应拒绝。
57. bundle 哈希必须对阶段输入顺序稳定；当前 120 次置换同哈希。但稳定哈希不等于运行时数据流稳定，也不等于生产可复现。

### 14.1 冲突字段默认交付（D39）

- `winner=null / deferred / skipped / authority-required` 是四种不同状态：未授权最终值、等待解除阻塞、按策略有意不执行、需要人工裁决。不得把未解决失败改标为 `skipped` 再算成功。
- 裁决粒度是字段；执行与发布粒度是能够独立成立的渲染单元。同一节点其他字段只有在不依赖争议字段、不制造假成品时才可写入；不得无条件阻塞全页，也不得机械地“能写几个算几个”。
- 默认交付矩阵：

| 字段 | `winner=null` 默认 | 节点策略 | 用户可见标记 |
|---|---|---|---|
| `text` | 不写候选正文，旧值不更新 | 依赖满足的其他内容可写，否则延迟单元 | 未决文本区域或报告；旧值标未重新确认 |
| `color` | 不写争议 fill，不自动取截图色 | 已有节点可不改；新节点避免误导默认色 | 颜色未决；占位色不是设计色 |
| `asset` | 不写未验证素材 | 槽位可靠才建占位，否则延迟区域 | `asset deferred` 或 `reference-only` |
| `visibility` | 不创建显隐未知节点 | 无 `visible` 能力时延迟创建 | 显隐未决或有意省略 |
| `geometry` | 不写争议位置和尺寸，不取平均 | 无有效锚点则延迟节点或区域 | `geometry deferred`；位置未知只列报告 |

- 旧内容保持不动只表示“未更新”；不能证明仍适用时标 `retained-unverified` 或 `carried-forward-not-seen`，并排除在本轮验证通过范围之外。
- 候选文本、冲突价格和未验证资产默认进入独立 `Conflicts / Unknowns` 报告，不进入最终内容层；报告至少包含对象/字段、双方观测、权威缺口、当前显示行为、不可做操作、待确认项和下一步。
- 截图-only 颜色只能记为 `rendered-color`；视觉近似 fill 需要显式 `visual-approximation` 政策、验证和降级声明，默认仍零命令。`flat-raster-crop` 只能作为获准的 `reference-only` 降级。
- tombstone 必须有删除范围、权威来源、版本和生效时间；`not-seen` 不是 `deleted`。能力不足或用户已改动时标 `delete-pending`，不得声称已删除。

### 14.2 写入失败、事务与回滚（D40）

- 层次固定为：字段裁决 → 单条命令尝试 → 依赖闭合的区域/小子树逻辑提交 → job 发布汇总。没有服务端事务能力时，只能做分阶段写入与补偿，不能宣称全有或全无。
- 默认流程：预检字体/资产/能力/父节点/参数 → 写入专用 staging 根 → 回读 → 区域验收 → 发布。当前 bridge 没有 `visible` 能力，staging 可能可见，必须标 WIP 并隔离，不能声称隐藏。
- 不确定结果分三种：命令未发送可安全重试准备；明确失败且确认无副作用可按类型重试；已发送但响应丢失必须标 `unknown-outcome`，先对账，不盲重发。
- 幂等意图键至少包含 `job_id / revision / logical_object_key / operation_type / payload_hash`。稳定名称只便于定位，不是唯一身份；客户端幂等键不会自动让创建操作幂等。
- 已确认节点存在且归属匹配才做精确更新；确认未创建才重新创建；重复名称、多候选、用户并发修改必须转冲突，不覆盖、不删除。更新能力不支持时可在新版本重建，但不能称为原命令的安全重试。
- 回滚优先新建受控 staging，不先改用户旧稿再依赖 undo。清理只针对本 job 明确创建且未被用户接管或修改的节点；删除前核对 ID、归属和当前状态；不使用全局 undo 回退未知并发操作。
- 写后最低验证分三层：返回 ID 证明写入确认；树/属性回读证明类型、父子、内容、几何、字体、图片和裁剪；区域渲染证明可见内容、缺字、溢出和叠放。导出失败标 `verification-pending`，节点已写成功不得因此重新创建。
- 失败分类至少覆盖：字体缺失、图片上传失败、权限拒绝、限流、父节点被删除、响应超时/结果未知、导出失败。可安全重试的操作最多 3 次并设总时间预算；无权限、字体缺失、尚未对账的未知结果不得反复重试。
- 新建任务默认专用 `Agent Output` 根 Frame，名称包含 job、revision 和 `WIP / PARTIAL / VERIFIED` 状态；锁定只防误改，不是事务或导出门禁。用户明确要求编辑现有稿时，限制到已授权目标，不按名称批量删除。
- 同 job、同 revision 恢复属于重试；用户要求第二版、证据/计划/政策变化时创建新 revision，不能在旧幂等键下更换 payload。

### 14.3 DOM 与截图权威边界（D41）

- `faithful` 的目标是指定状态的可见渲染，但截图不因此接管全部语义。DOM 负责经验证的来源事实，截图负责可见外观证据；原始 DOM 文本、可见文本、CSS 声明色、合成像素色必须分开，不能让不同类型的量竞争同一个 winner。
- 状态不一致时先重采或分版本，不能用“截图更像最终画面”掩盖过期来源。来源切换必须记录目标字段、原因、证据、能力和授权；不允许整节点一键切权威。
- 伪元素/CSS content 以同状态已求值内容、样式和渲染核对为准；canvas 文本由图像证据管外观，OCR 或确认后才晋升为文本；跨域 iframe 只有获准且可访问的子文档才能采集；closed shadow root 只能保留可访问的渲染证据；DOM 隐藏文本不写成可见节点；截图-only 文本只晋升 `text-content` 候选；z-order 以核实后的局部绘制关系为准。
- 确认不显示的 DOM 文本：新稿按策略省略并保留证据；`visibility` 未知则 `deferred`；旧节点本来可见、现在应隐藏却无法操作时，必须报告未完成，不能声称已忠实更新。
- `background-image` 是资产引用加使用实例，渐变通常是 fill，filter/blend 是效果和合成，伪元素可承载文字、图像、fill 或效果。原生样式能产生目标渲染时保留原生色和效果；截图像素因 opacity/blend/filter 偏离 CSS 色，不说明 CSS 错了。
- 原生无法等价时，只能在显式获准后局部 `reference` 栅格降级；不能抽取一个合成像素作为新 CSS fill 并声称精确恢复。普通可见文字可晋升转写；logo、艺术字、符号宜保持素材或经确认的图标；字形编码不自动等于语义字符。
- 过期 DOM、水合和缓存：记录 M0/S/M1、可见文本映射、页面变化与加载状态、目标 URL、状态签名；不一致先标 `state-mismatch` 或 `external-conflict`，再有限重采；无法稳定则 `unknown` 或 `partial`，不自动改成截图轨。
- `external-conflict / unknown / unsupported` 分别表示可比矛盾观测、证据不足或不可访问、要求明确但能力不足；三者可分别出现在证据、决策和能力层，不压成一个互斥字段。
- OCR 晋升：双引擎 exact + `0.85` + `0.50` 是给定实验的候选门槛，不是全站正确率保证。无 DOM 时，风险低、清楚可见、状态和身份通过、内容核对通过可晋升 `text-content`；价格、歧义、关键编号、可见性冲突和未覆盖样式必须人工或权威确认。晋升文字内容不自动晋升 `editability / role / asset_source`。

### 14.4 部分成功与不可交付区域（D42）

- 默认同时提供用户可见报告和机器 manifest。业务根名称例如 `[PARTIAL] 页面名称 · revision`；报告包含缺口、图例和受限操作。状态不能只藏在图层名里，manifest 也不能替代用户看得见的告知。
- 位置可靠时，未交付区域使用带文字、图例、中性斜线并明确“未交付”及原因的草稿/覆盖图，它不是原设计内容；位置不可靠时只列未定位清单，不编造矩形。最终内容与诊断层分离，不用红块遮挡有效内容，不用空白冒充页面本来没有。
- 保留语义名称再加状态，例如 `[deferred] 书名`、`[conflict] 价格`、`[reference-only] 横幅`、`[write-failed] 卡片`；不存在的内容节点不为加标签而伪造；名称不替代稳定身份与 manifest 映射。
- coverage map 至少包含 `region_id`、source/output 坐标系与映射、有效/未知/省略/失败/参考状态、原因、证据、可做/禁止操作、受影响维度、对象键；面积、对象、文字、关键项覆盖分别报告，重叠面积按并集。
- 防止误认为最终稿：根名或横幅、独立报告、受控导出 release gate 三者组合。锁定只防误改，独立页面也不能阻止手动导出；不能承诺绝对禁止导出。自动导出可要求完整验证令牌或显式 partial 导出确认；没有能力时不假称已设置门禁。
- 用户摘要至少包含目标/profile、可用区域、`deferred / skipped / conflict / failed` 计数、`reference-only` 范围、关键阻塞、不可做操作、所需补证/确认和下一步；计数注明是字段、对象还是区域，不能混加。
- 诊断占位可从已验证有效区的局部 diff 排除，但原始要求范围的分母不能缩小；必须同时展示 masked diff、有效覆盖、未测区域和失败区域，排除区不能变绿或标 pass。
- 四种空缺分开记录：`intentional-omission / write-failed / observed-absent / not-captured`；删除和 tombstone 另记权威及动作是否落实；`not-seen` 不能转为 `deleted`。

### 14.5 四维验收与页面级发布（D43）

- 先声明合同：交付范围 `S`、每区域 required 维度与能力、关键项 `K`、允许降级、排除范围和证据覆盖要求。四维状态是评估结果，`release_status` 是发布决策，两者不得共用一个字段。
- 硬门禁：视觉、结构、编辑、资产分别给出 `pass / partial / fail / unknown` 的最低条件；某维度不适用时记 `applicability=not-required` 并说明理由，不伪装为 pass。`faithful` 必需视觉；约定结构可编辑时结构必需；约定编辑能力时编辑必需；资产按具体要求判，不以面积抵消。
- 页面汇总顺序：前置门禁（授权、目标状态、IR 完整性、写入归属）→ 逐项验证并保留对象/区域/未测项 → 关键项 `fail / unknown / 未允许 partial` 阻断原合同 → 非关键缺口可隔离且用户允许时输出 `deliverable-partial`，缺口仍留在原合同分母 → 全部 required 满足且覆盖充分才输出 `deliverable-complete` → 只有参考用途成立时输出 `reference-only`。视觉 pass 不能抵消编辑 fail。
- 覆盖率：不存在通用“至少 95% 或 N 个样本就 pass”。每个关键 required 对象或字段应 100% 执行适用检查；未采样区域不能获得对象级 pass；页面级抽样结论必须带推断范围和经过验证的采样政策。发现 fail 后，不能因为还有未测项就改判 unknown。
- warning 只用于合同容差内已标定的抗锯齿/像素噪声或获准的非关键参考资产降级；错字、缺字、关键断行差异、遮挡不得自动 warning；改变排版或违反 `faithful` 的单行断行差异应阻断对应项。
- 未标定站点可对直接可核实的事实判 pass，例如原生文本与目标内容确切一致；自动视觉和字形分类不能借用合成集阈值并无条件通过。可记 `provisional` 或 `unknown`；`provisional` 是验证资格，不是第五种通过分数。Firefox 未覆盖就不宣称支持 Firefox；目标明确限定为已验证 Chromium 时，Firefox 未知不阻断该限定发布。
- 最小验收记录：对象键、要求、criticality、维度、参考/profile、证据、指标/单位、阈值来源与版本、实际值、适用范围/覆盖、未测原因、状态、原因、修复建议、验收版本与时间；`not-sampled` 与 `no-ground-truth` 都不进入通过分子。
- 三种发布口径：试点（限定场景、人工复核、明确 provisional、安全隔离、不隐去失败）；可交付（当前用户合同在已标范围满足，partial 是受限交付而非完整通过）；生产（除效果验收外，还需故障恢复、幂等与对账、权限及并发安全、持久化迁移、重放、保留政策、限定环境覆盖和监控）。不能靠一次画板写入成功推导生产可用。

### 14.6 生产 IR、持久化与重放（D44）

- 最小分层 schema：job/合同、capture、node、field、evidence、asset/use、写入计划与结果、验收与发布。不是每个节点都需要 entity/slot，不适用时明确记录；字体 run、裁剪、tombstone 按类型必需；大字节、原始 HTML 和诊断明细可外置，但必须有可靠引用。
- 不能用缺字段或 `null` 同时表示未知、删除和不适用；未知使用带 reason 的状态。观测、裁决和 provenance 都保留；影响裁决、冲突和发布的候选与来源不得删除。体积控制依靠引用去重、分块、配额、生命周期和授权范围，而不是丢弃失败候选。hash 证明内容身份，不替代字节，也不能重建过期图片。
- 版本至少分开记录 `schema_version / policy_version / capture_revision / plan_revision / output_revision` 和写入、验证能力版本；采用不可变快照与追加事件，持久化需要崩溃一致性。兼容变化增加有定义的可选项，破坏性变化升级主版本；迁移生成新副本并保留原件、迁移链和前后 hash；未知版本或枚举失败关闭，不静默补默认 winner，不因迁移改写资产和证据。
- TTL 建议起点：终态后保留可重放证据 30 天、最小脱敏审计元信息 180 天；需用户或组织政策确认，不是法规要求或永久承诺。敏感任务可更短；长期未终态任务需独立闲置过期规则。每对象记录 `retention_policy / expires_at / 访问权限 / 删除状态`；外部临时 URL 有效期与本地证据保留期分开；密码、cookie 和访问令牌不作为审计证据保存。
- 证据过期后可保留获准的 hash 和决策摘要用于审计，但标 `evidence-unavailable`，不能声称可精确重放。重新采集建立新 capture 和 revision，需获准；不能用新页面替换旧证据再声称原运行可复现。
- 三种重放语义分开：`audit-replay` 重演旧决策链，证据不齐时只做摘要审计；`materialize-replay` 复用锁定证据、政策和计划再生成输出，字体或渲染环境变化时应重新验收，不保证逐像素一致；`recapture-reconcile` 重新访问来源，形成新参考和新决策版本。同 job 失败恢复另记 `resume`，只处理已对账的未完成操作。
- 首次 Figma 副作用之前必须持久化：合同与授权、锁定 IR 与证据可用清单、决策/冲突/tombstone、能力快照、输出归属与前置基线、计划与依赖、plan/payload hash、幂等意图和恢复政策。每次发出前持久化该操作 intent，返回/回读/验收后追加结果；持久化失败则不写。这仍不能消除“副作用成功但归属 ID 尚未落盘”的服务端能力缺口。
- 离线审计 bundle 与运行时 IR 使用两个外层 schema，共享字段、证据、决策类型和版本字典。审计 bundle 强调有序证据与检查结果；运行时 IR 必须有可执行依赖 DAG、前置条件、写入状态和恢复状态；`ordered-audit-only` 不能自动变成执行顺序或运行依赖。
