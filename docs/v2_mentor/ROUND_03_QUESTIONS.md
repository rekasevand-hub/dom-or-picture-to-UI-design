## R3-Q01 截图输入、参考状态与 `faithful/adaptive` 契约

**已知事实**

- R1 明确：不同截图里的轮播、懒加载、裁切状态不能拼成一个假定的共同真值。
- R2 已建立 `capture_id`、M0 → S → M1、`complete / partial / rejected` 等参考状态规则。
- 截图路线没有 DOM 可做同态测量，输入证据更弱。

**为什么问**

截图路线首先要回答“这张图代表什么状态”。如果输入视口、缩放、浏览器外观、滚动位置和显示状态不清，后续分组与坐标比较都不可复现。

2. 单张截图、同状态多张截图、不同状态截图分别能支持哪种 `faithful` 结论？哪些比较必须拒绝？
3. 用户上传截图没有原始 DPR、视口或字体信息时，2.0 应如何声明不确定性和坐标换算依据？
4. 截图包含浏览器外框、滚动条、弹窗或同意条时，哪些属于页面内容，哪些应分离为截图外观层？

## R3-Q03 OCR、文本层重建与可编辑性

**已知事实**

- R2 已规定文本必须区分源值与输出值、逐 run 字体、行盒/基线证据和四项独立验收。
- 截图路线没有原 CSS，字体、字号、行高、换行和字形都只能从像素推断。
- R1 反对“文本盒看起来对就宣布文字 1:1”。

**为什么问**

OCR 只能提供字符候选，不等于真实文本层；把 OCR 结果直接当可编辑文字，可能同时引入内容、换行、字体和基线错误。

**请导师回答**

1. OCR 结果进入可编辑文本层的最低条件是什么？置信度、行框、字符几何和人工复核应如何组合？
2. 应优先还原逐行文本、段落文本，还是保持视觉行？中英混排、数字、标点、省略号分别怎么处理？
3. 字体、字号、字重、行高和字距无法从截图唯一确定时，应记录哪些候选与状态？是否允许用默认字体先重建？
4. 哪些文本应保持为图片/轮廓（如品牌字标、艺术字、无法可靠识别的文字），哪些必须转成原生文本？
5. OCR 识别出的内容与画面可见字形冲突时，以哪个为准？如何报告不确定性，避免“脑补”被遮挡或模糊文字？
