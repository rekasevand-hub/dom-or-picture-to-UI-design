## R3-Q01 截图输入、参考状态与 `faithful/adaptive` 契约

### 本次实际做法

- 上传截图原像素尺寸为 2544×4959。
- 没有获得可靠的：
  - DPR。
  - CSS 视口。
  - 实际字体声明。
- 此前 URL 截图有已设置的浏览器视口，但不能把这些信息移植给上传截图。

### 通用做法与 2.0 建议

#### 1. 最低输入字段

- `reference_id`。
- 来源、授权范围。
- 内容 hash。
- 格式。
- 原像素宽高。
- 当前缩放、裁切、变换。
- 单屏／全页／拼接／未知。
- 已知时间。
- 参考范围。
- `profile`。

以下已知则记，未知则 `unknown`：

- DPR。
- CSS 视口。
- 浏览器缩放。
- 滚动。
- 语言、字体。
- 轮播、占位、遮挡。
- 浏览器外观。

解码后的方向也要明确，避免使用未应用方向的坐标。

#### 2. 不同截图组合的结论边界

**单图：**

- 只支持可见范围、该显示状态的 `faithful` 结论，不证明被遮挡或屏外内容。

**同态多图：**

- 可以验证重叠、提高覆盖，但要有一致内容、尺度和状态证据，不能只看名称相近。

**不同状态：**

- 分别建立 reference／state。
- 不能拼出一个“原来就如此”的共同真值，也不能将状态差直接算作几何误差。

#### 3. 元信息缺失时的坐标依据

- 以源图像素坐标重建。
- 若仅均匀缩放，定义：`canvas = s × source + offset`。
- 不凭图片宽度反推 CSS 视口或 DPR。
- CSS 尺度未知时，不用 CSS px 报告精度。

#### 4. 浏览器外观与页面 overlay

- 地址栏、系统外框：截图外观层。
- 滚动条：可能是浏览器，也可能是网页自定义；来源不明则单独标 `unknown`。
- 网页弹窗、cookie 条、遮罩：页面显示状态，作为 overlay 保留，不占常规 flow。
- 不能因为遮挡，就静默删除。
- 复现整图还是仅复现网页内容，应先明确范围。

#### 5. adaptive 不能从单图证明

- 截图可以提出 `adaptive` 候选，不能证明原规则。
- 默认 `faithful`。
- 变列、增高、截断、编辑范围，应由用户明确给定，或由建议方案经确认后采用。
- 固定坐标或 flow 只是实现方式，不能悄悄改变参考外观。

#### 6. 拼接长图最低证据

- 每段 hash。
- 顺序。
- 像素范围。
- 重叠、接缝。
- 缩放、裁切。
- 已知滚动、时间。
- 重复 fixed 区域。
- 状态差异。
- 内容缺口。

来源过程未知时，标 `composite-unknown`。可以将“这张图本身”作为视觉参考，但不能视为真实单一页面布局状态。

### 依据 / 可复现证据

建议实验：

- 同图不同缩放，经已知变换对齐。
- 轮播不同帧建立不同 reference。
- 长图分别检查接缝、重叠和重复头部。

没有元信息的样本应报告 `unknown`，不自动生成 DPR。

### 不确定项

用户图的真实 CSS 尺度、捕获机制、字体和完整状态，无法确认。

### 失败或放弃的方案

无新增实验。

不将多时刻素材、视口猜测、不可见内容拼成同一状态事实。

### 我的备注

忠实复现一张合成图，不等于证明它对应某个可复现的网页瞬间。

## R3-Q02 从像素建立语义分组与层级

### 本次实际做法

- 上传截图版采用粗区域固定结构，没有事先执行统一分组规范。
- 当时具体采用何种识别或分区步骤，无法确认。

### 通用做法与 2.0 建议

#### 1. 不设单一视觉信号的绝对优先级

先划定页面、overlay 和截图外观范围，再综合：

- 标题与内容关系。
- 共同背景、边界。
- 留白、对齐。
- 重复模式。

明确的栏目标题与内容关联，通常比单纯视觉接近更强。跨区域共享白底，不是合组证据。

#### 2. 从视觉块升级为语义对象

独立栏目候选需要明确作用域，并有相互独立的支持，例如：

- 标题关联＋内容集合。
- 共同边界＋内部一致排列。

重复卡片候选需要：

- 角色组合重复。
- 视觉模式重复。
- 可解释的内容边界。

两个近似矩形不足以确认卡片语义。“两种证据”只是审查起点，不是自动正确的数学门槛。

#### 3. 区域边界规则

采用页面区域、栏目、布局行列、卡片、元素层级，但不强制固定树深。

- 侧栏与主栏可以位于同一布局行，仍保留独立栏目身份。
- 页脚不与上一组排行合并。
- 弹窗属于独立 overlay。
- 焦点与导航分开。
- 跨区域背景或装饰单独管理，不为它合并语义区域。

#### 4. 语义不明时保留最小 unknown 区域

- 不为凑树强合并，也不把每个像素块都拆成语义对象。
- 能明确分开的对象可以独立保留；未知父关系在 IR 中表达。

#### 5. 单子项、裁剪、装饰的证据边界

单图通常无法唯一确定：

- 单子项是否承担对齐。
- 某窗口是否只负责裁剪。
- 装饰是否影响布局。

记录用途候选和替代解释。“看起来居中”不能证明 Hug／Fill 关系。裁剪 Frame 可以成立，但语义职责、布局职责分别评估。

#### 6. IR 与人工修订

分别记录：

- `object_id`。
- `role`。
- `parent_relation`。
- `pixel_region`。
- `boundary_evidence`。
- `semantic_evidence`。
- `alternatives`。
- `evidence_status`。
- `review_status`。

重新分组可以改变父关系版本，不应使所有已识别对象身份重建。拆分、合并保留 lineage。检测框是估计区域，不是已知 CSS 容器边界。

### 依据 / 可复现证据

建议实验：

- 相同白底的主栏与侧栏。
- 无边框卡片。
- 跨多个栏目的有边框背景。

检验是否避免按最近距离合组。人工只改父关系后，对象身份应保持可追溯。

### 不确定项

原父子关系、组件定义、真实内容语义，不能仅凭像素完全确认。

### 失败或放弃的方案

不采用：

- 每个有框区域都是组件。
- 所有相邻区域合组。
- 视觉框越多，结构越可编辑。

无历史分组失败实验可引用。

### 我的备注

分组是有证据的假设。语义标签的确定口吻，不等于确定性证据。

## R3-Q03 OCR、文本层重建与可编辑性

### 本次实际做法

- 前轮确认上传版有 160 个原生文本层，统一 140% 行高。
- 但没有完整记录：
  - 逐字 OCR 复核。
  - 实际字体。
  - 基线。
  - 识别置信度。
- 不能声称这些都已经验证。

### 通用做法与 2.0 建议

#### 1. 原生文本准入最低条件

- 来源区域。
- 可见字符候选。
- 阅读方向、行序。
- 未识别片段。
- 内容核对状态。

OCR 分数保留原始口径，不当作跨语言、跨识别方式通用的真实概率。高分不能覆盖画面冲突。金额、日期、姓名、编号等证据性内容需要更严格复核；低清或冲突项不自动定稿。

#### 2. 逐行还是段落

- `faithful` 先保持可见行序与断行。
- 能够可靠重建同一段落和断行时，优先原生段落。
- 否则可采用：
  - 显式换行。
  - 逐行文本。
  - `line-preserved` 标记。

逐行层可编辑，不代表段落可重排。`adaptive` 需要另外定义段落边界与换行规则。中英、数字、标点逐项核对。可见省略号只保留可见内容，不扩写被截断的标题。

#### 3. 字体与排版参数不唯一时

记录：

- OCR 原文、修订文。
- 候选字符。
- 可获得的词、行、字符范围。
- 来源框。
- 字体候选、依据。
- 字号、字重、行高、字距估计。
- 输出值。
- 替代状态。

截图里的字体参数通常不能唯一确定。明确允许近似时，可以使用已声明的可用字体制作草稿，但不能标精确复刻。已有缺失字体时，替换须获准。

#### 4. 原生文字与素材文字

- 导航、正文、书名、作者等普通 UI 文字，目标应为原生文本。
- 无法可靠识别时，标局部 `partial`，不能把文字图片充当完成。
- 品牌字标、艺术字可以作为素材保留。
- 没有原始矢量时，轮廓化也不是原文字资源，不能宣称是可编辑文字。
- 无法辨认时保留证据像素，候选转写放在报告里，不用猜测覆盖原图。

#### 5. OCR 与画面冲突

- `faithful` 以可见字形证据为准。
- 不根据 OCR 候选、常识、上下文补全不可见文字。
- 遮挡、压缩、模糊片段可标 `unknown`，并附区域和候选。
- 用户确认补文另记 `user-supplied`，不能冒充截图中可读的事实。

#### 6. 文本阈值需要重新标定

- CSS 尺度未知时，以源图像素计；缩放已知再换算。
- 截图无法唯一恢复文本容器框，应称：
  - 可见文字区域。
  - 重建框。
- 不能假称原 CSS 盒。
- 可靠基线缺失就 `not-evaluated`。
- 抗锯齿、压缩、缩放均需重新标定。
- 内容与换行仍要独立核对，不能靠字形相似掩盖错字。

### 依据 / 可复现证据

建议实验：

- 相似汉字。
- `0 / O / 〇`。
- `1 / l`。
- 全角标点。
- 三点与省略号。
- 模糊截断。
- 中英混排。

分别测内容、断行、框、字形，不只算文本框重叠。

### 不确定项

原字体、字号／字距唯一解、被遮挡文本、原段落边界、可靠基线，无法确认。

### 失败或放弃的方案

不采用：

- 一个通用 OCR 分数阈值保证正确。
- 统一 140% 替代行高证据。
- 按上下文补齐不可见文字。
- 把轮廓文字算作可编辑正文。

### 我的备注

文字能被选中修改，是能力事实，不是内容、字体或排版准确的证明。

## R3-Q04 素材切分、复用与 reference-only

### 本次实际做法

- R1 抽查和学生统计表明，两种截图稿多处引用共享全页图，通过负偏移和父级裁剪显示局部。
- 不代表每个素材都已有独立原图。

### 通用做法与 2.0 建议

#### 1. 独立裁片候选条件

- 可隔离的可见边界。
- 足够分辨率。
- 没有必须保留的外部内容叠入。
- 明确的替换槽位。

重复出现可辅助确认，但不能恢复缺失像素。扁平截图一般无法证明透明通道，不能把与底色相同的区域当作真实透明。

#### 2. 文字、底色、阴影重叠时

- 书封内印刷文字属于素材。
- 封面外标题、作者属于 UI 文本，宜分离。
- 以下难以隔离时，保留为 `reference-only` 合成区域：
  - 图标抗锯齿带底色。
  - 阴影落在纹理背景上。
  - 文字覆盖照片。
  - 复杂透明叠放。

重画或去背景会改变证据，应另行授权、标记改作，不自动声称还原原素材。

#### 3. 同图多次出现不等于可恢复完整源图

- 相同裁片像素 hash 相同，可以去重复用。
- 尺寸、裁切不同，仅视觉相似不能证明同一原图。
- 分别保留派生裁片与 `same-source` 候选关系；共同内容和尺度证据充分时再关联。
- DOM 有原资源可去重，不等于截图里也能恢复同一完整资源。

#### 4. 各类型优先策略

- 简单形状、圆角、边框、分隔线：优先原生。
- 图标：准确已知矢量或简单几何候选优先。
- logo、艺术字：保留证据素材，除非有准确矢量来源。
- 渐变、阴影：参数属于推断，验证达标才采用原生。
- 纹理、照片、书封：保留栅格。

不能因为矢量更“高级”，就牺牲准确性。

#### 5. 低清、压缩、遮挡

- 保留现有证据和限制，可以交付局部参考，不能宣称独立完整素材。
- 其他状态截图不得静默补全。
- 补证需要明确授权、新 reference 版本，并报告非原图来源。本轮不做融合。

#### 6. 澄清 derived 与可替换性

R2 枚举中的 `derived` 描述“派生裁片来源”，不自动证明可替换。

建议分成两个字段：

- `provenance`：
  - 原资源。
  - 截图裁片。
  - 共享裁剪。
  - 原生重建。
- `replaceability`：
  - `independent`。
  - `constrained`。
  - `reference-only`。
  - `missing`。

兼容旧 `derived` 字段时，必须附替换能力。逐项报告来源、边界、分辨率、合并内容、替换范围和限制。可导出局部图片，不等于可无损更换素材。

### 依据 / 可复现证据

建议实验：

- 同封面不同裁切。
- 文字盖图。
- 带阴影图标。
- 低清 logo。
- 要求只替换目标，检查邻近文字和背景是否被一并替换。

### 不确定项

原素材完整边界、透明度、被遮挡内容、不同裁片的同源关系，无法确认。

### 失败或放弃的方案

不采用：

- 每个裁片都是原始素材。
- `derived` 必然可独立替换。
- 根据近似外观补造 logo 或封面。

### 我的备注

以下是四项不同能力：

- 来源可追溯。
- 可导出。
- 可独立替换。
- 素材内部可编辑。

需要分别报告。

## R3-Q05 截图路线能否推断 true flow

### 本次实际做法

- 一版截图稿有大量 Auto Layout，另一版没有。
- 前轮没有内容扰动通过记录，因此不能把任一整版标记为已验证 true flow。

### 通用做法与 2.0 建议

#### 1. candidate 最低门槛

- 可解释的顺序、主轴。
- 明确作用域。
- 重复角色。
- 间隔、对齐证据。
- 尺寸策略可以闭合。
- 重叠可以独立解释。
- 文字和素材几何足够稳定。

单子项对齐也可以进入候选，但不能只凭视觉居中推断原 Hug／Fill。证据不足时保留固定区域或 `pending-evidence`。

#### 2. 无扰动实验，不标 verified

分别记录：

- L1：已设置。
- L2：布局确实参与。
- L3：在声明测试范围内行为正确。

即使 L3 通过，也只证明本次输出，不证明网页原规则。

建议字段：

- `verified_for=output-contract`。
- `source_behavior=inferred`。

#### 3. faithful 和 adaptive 的允许操作

- `faithful` 可以内部重组或采用 flow，但要求指定状态外观和内容不变。
- 不能引入：
  - 新断行。
  - 隐藏项。
  - 未获准响应式假设。
- `adaptive` 的变列、增高、截断、最小宽度等，应由用户给定或经确认的方案提供，并记录 `accepted-by` 和版本。

一次截图不能自动证明原站规则。

#### 4. 各类区域候选策略

- 页面区域：纵向。
- 卡片集合：行横向＋列表纵向。
- 卡片信息：纵向。
- 页头：按真实视觉子区拆分横纵。
- 主栏与侧栏：同一横向区域，各自内部纵向。
- 页脚：按内容行组织。

尺寸默认忠实于证据，Fill／Hug 不是默认。

建议实验：

- 长标题。
- 实际高度＋40。
- 条目增删。
- 宽度变化。
- 主栏、侧栏高低交换。

两层 stack 跨行重组仍需显式规则。

#### 5. 保留固定坐标的边界

- 复杂叠放。
- 疑似拼接。
- 装饰不可分离。
- 文本不可靠。
- 存在多个同样合理的排列。
- 转换后几何超阈值。

发现错序、丢项、非预期遮挡、传播不符、装饰脱锚，应回退该区域。可以保留“父 flow＋子固定”，但披露限制。

#### 6. DOM 与截图冲突时

截图轨只记录 `external-conflict` 及对应 reference，不用 DOM 覆盖截图证据。R4 前，资产、状态、结构清单保持来源隔离。需要跨轨确认时停在未决项，不把外部结论写成截图已观察事实。

### 依据 / 可复现证据

单张静态图不能区分多个能够产生相同像素的布局。

建议实验验证的是：所选输出规则是否满足已批准的编辑合同。不是验证“猜对了原站”。

### 不确定项

原布局、响应式断点、编辑后原站行为，未知。

### 失败或放弃的方案

- 不以 Auto Layout 数量或一次渲染成功评优。
- 不把 DOM 覆盖当作截图路线自动纠错。

### 我的备注

分别记录：

- 语义证据。
- 静态视觉通过。
- 输出布局行为通过。

避免一个 `verified` 掩盖不同范围。

## R3-Q06 四项验收、阈值与部分成功报告

### 本次实际做法

- 前轮没有完整四项验收或像素误差报告。
- 不能补发三版的总分或精确通过率。

### 通用做法与 2.0 建议

#### 1. 四项最低报告字段

每项记录：

- 对象、范围。
- 要求。
- 证据。
- 指标、单位。
- 阈值来源。
- 实际结果。
- 覆盖。
- 未测项。
- `pass / partial / fail / unknown`。
- 原因、修复建议。

各维度分别检查：

- 视觉：几何、内容、字形、像素。
- 结构语义：角色、边界。
- 编辑行为：原生文本、布局扰动。
- 资产：替换合同。

不能以图片可见代替资产可替换。

#### 2. 缩放换算

明确定义：`s = 画布长度 ÷ 源图像素长度`。

均匀缩放时：

- `画布阈值 = s × 源图阈值`。
- `源图误差 = 画布误差 ÷ s`。

CSS 尺度未知，就不报 CSS px。源图 1 px 只是起始几何容差，不代表所有压缩、插值误差都被豁免。非均匀变换分别记录，不能套单个 `s`。配准只采用声明的坐标变换，不局部拉伸来隐藏错位。

#### 3. 四类评级

| 状态 | 含义 |
|---|---|
| `pass` | 该项合同在声明范围内全部满足 |
| `partial` | 有已验证的可用子集，且缺口明确 |
| `fail` | 要求与结果存在明确矛盾 |
| `unknown` | 证据不足或未测 |

例如：

- 视觉像、结构错：视觉可以 `pass`，结构 `fail`。
- 结构合理，但要求原生的正文是图片：编辑 `fail`。
- 要求独立替换，但只有 `reference-only`：资产 `fail` 或局部 `partial`，不能整体 `pass`。

#### 4. 文本误差分项

分别记录：

- 内容转写。
- 可见断行。
- 字体替换。
- 文字区域。
- 基线。
- 字形。

可以汇总文本问题数，但保留子项。基线未测是 `unknown`，不是误差 0。字体替代可以形成可用草稿，不等于原字体验收通过。

#### 5. partial 的适用条件

只有关键目标仍存在可用范围、缺口可隔离且不误导使用时，整体 `partial` 才成立。核心正文错误、关键资产不可替换、状态整体不可用时，不能用其他区域平均掉失败。

`partial` 应附：

- 有效、不可用区域。
- 缺口清单。
- 证据等级。
- 影响。
- 不可做的编辑。
- 人工复核项。
- 建议动作。
- 是否满足最低目标。

不编造概率。

#### 6. 固定样例集

| 类型 | 最低验收重点 |
|---|---|
| 中文 | 标点、禁则、断行 |
| 英文 | 字距、长词、连字 |
| 混排 | 字体 run、数字、基线 |
| 图标与 logo | 细线、品牌细节 |
| 复杂背景 | 透明、阴影、叠放 |
| 长页 | 接缝、重复头、缺项 |

每类含清晰与困难输入，四项分别打标。保留独立标定集和验收集，不只报告平均像素相似度。

### 依据 / 可复现证据

建议实验：同一样例分别引入：

- 一个错字。
- 一处遮挡。
- 一张不可替换合成图。
- 一个不传播高度的容器。

检查报告能否定位到对应维度，而不是统一显示“95% 相似”。

### 不确定项

经标定的阈值、输入噪声底、人工标注一致性、各项实际得分，未知。

### 失败或放弃的方案

- 不使用单一像素分数代替四项。
- 不把 `unknown` 自动当作可接受误差。
- 不以部分成功掩盖核心目标失败。

### 我的备注

评分分母必须说明是：

- 页面。
- 区域。
- 对象。
- 字符。
- 被测用例。

未覆盖部分不能进入通过分子。

## R3-Q07 失败、停止与人工接管边界

### 本次实际做法

- 没有本轮拒收或人工接管实验。
- 历史证据不足以给出通用最低分辨率和失败率。

### 通用做法与 2.0 建议

#### 1. 拒绝完整重建承诺的条件

- 输入损坏、不能解码。
- 来源范围不明且无法授权。
- 关键内容不可辨。
- 严重接缝破坏导致几何无法确定。
- 状态互相矛盾，无法指定权威参考。

不是所有低清或不完整截图都必须整页拒绝。用户只需要可见局部、局部证据足够时，可以局部输出。不存在适用于全部文字、全部屏幕的统一最小像素宽度。

#### 2. 局部输出与整页停止

缺图、模糊、语义不明可以隔离时：

- 保留有效区。
- 提供源坐标下的无效区域或遮挡掩码。

缺口决定整页尺度、顺序、关键正文、全局状态时：

- 停止整页布局验证。
- 可以保留来源图和未验收草稿。
- 不能标作可用成品。

#### 3. 遮挡不靠上下文补全

- 优先保留证据像素，转写或结构中标 `unknown`。
- 占位说明放在报告或草稿层，不伪装成原图内容。
- 用户补文记录为 `user-supplied` 及版本，另做验收。

#### 4. 人工接管只索取最小必要证据

| 阻塞项 | 最低补充证据 |
|---|---|
| 模糊文字 | 原分辨率图或准确转写 |
| 字体 | 字体信息、可用字体或替换授权 |
| 分组歧义 | 确认候选父关系 |
| 拼接 | 分屏原图、顺序 |
| 素材遮挡 | 原素材 |

不是每次都要求 DOM。提供 DOM 会改变本轮证据范围，需要另行同意并记录路线变更。

#### 5. 失败／部分成功 manifest

至少记录：

- 输入 hash、尺寸、变换、参考状态。
- `profile`、目标。
- 问题区域、类型。
- 内容候选、未知项。
- 分组、字体、资产降级。
- 已尝试动作、结果。
- 重试或停止原因。
- 输出对象映射。
- 有效、无效覆盖。
- 四项状态。
- 需要人工补充的证据。

只记录必要内容，敏感截图与转写按授权处理。

#### 6. 截图路线与 URL 自主截图降级的边界

- URL 自主截图降级解决：如何取得参考。
- 截图重建解决：这份参考能支持什么输出。
- 进入截图轨后，不能继承未采到的 DOM 事实。
- 缺陷来自未加载、错误视口、错误状态、接缝时，应要求重新采集，而不是继续猜。
- 只能提供现图时，报告局部能力。
- 新截图建立新 reference，明确权威版本，不静默混用旧新状态。

### 依据 / 可复现证据

建议实验：

- 局部模糊、主体清晰。
- 关键数字被遮挡。
- 整页拼接错序。
- 不同轮播帧。

预期分别可能输出：

- 局部 `partial`。
- 关键项 `blocked`。
- 整页 `rejected`。

而不是总能给出完整页面。

### 不确定项

具体输入可恢复程度、用户最低目标、可用补证，需要逐例判断。

### 失败或放弃的方案

无新增失败记录。

不补造不可见内容，不无限重试同一证据，不把美观草稿当作事实恢复。

### 我的备注

停止的是超出证据的承诺，不一定是所有有用工作。可交付范围必须与已验证范围一致。
