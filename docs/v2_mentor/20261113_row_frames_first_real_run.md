## 1. 坑一：分区绑在了另一版设计上

探针读 `figma_design.json`（校准四轮后的终版），mvp 却把分区套在**校准前**的设计上。

| | 值 |
|---|---|
| 坐标不同的元素 | **89 / 152** |
| 像素 | 带开关 **59.37**（基线 95.60） |

修法：`design_fingerprint()` + `--dump-partition-design`，分区文件写 `designSha256`，
应用前比对，不一致就 `blocked-environment`。

## 2. 坑二：被拒的容器被画成默认灰

`resolve_frames` 拒掉一个组后，容器退回普通矩形；没有 `fillColor` 时插件填
Figma 默认灰 `#d9d9d9`——一页 10 行就是 10 条灰带，像素差 **26.34%**。

修法：容器自带 `fillColor/borderColor: transparent`。

## 3. 坑三：透明容器的深度（自己引入的）

第一版修法是「透明容器不参与覆盖计数」，但顺手把它**自己的深度也固定成 0**：

```
祖先区块 depth=1，行 Frame depth=0 → Frame 排在祖先之前
→ 祖先落进 `resolve_frames` 的「Frame 之后」窗口 → covers-other-element
```

light-form 12 个组全灭、light-table 掉到 1/10 都是这条。正确形状：透明容器不参与
**别人**的覆盖计数，自己的深度仍按「被多少不透明元素覆盖」算——算出来正好是成员
那一层，靠下标（容器插在最早成员之前）决定它先于成员落笔。

## 4. 坑四：容器矩形冻结，成员却被校准搬走

`行 08` 的 7 个文本整体左移 11px、上移 6px；`行 01` 的 `执行时间` 从 (1366,142)
挪到 (1752,286)。容器 bbox 冻在分区那一刻 → `member-outside-frame` / `member-before-frame`，
12 组只剩 4 组建成。

修法：`refresh_partition_containers()`，每次发射前按**当前**几何重建矩形与成员表；
成员全丢的容器从列表移除（否则留一个永远建不成的空框）。

## 5. 坑五：帧内文本让校准回路跑飞（最贵的一个）

把容器插在**校准之前**后，native 从 30/33 掉到 23/33。逐条追：

| 现象 | 数值 |
|---|---|
| `名称` 渲染墨迹 | 25×12（参考 33×16） |
| 字号 | 17.75 → **13.5** |
| `复制` 字号 | 16.75 → **13.25** |
| 触发者 | `ink-convergence`：量到 21×25，判「太大」 |

根因有两层：

1. 帧内 TEXT 的 `bounds` 是**相对父帧**的，而校准拿它当页面坐标写回 `textBox`
   （写成 `(12.5, 6.5)` 而不是 `(318, 507)`），下一轮渲染再减一次帧原点 → 标签飞到
   画布左上 `(−294, −496)`。修法：`_text_nodes()` 沿父链累加，与测量侧
   `_text_node_boxes` 同一约定（根帧 children 起始、原点 (0,0)）。
2. 即使坐标对了，**校准回路一旦看到帧，测量窗口就会变**（1px 级别），
   `ink-convergence` 会据此改字号，然后整条链跟着漂。

所以最终定案：**校准在扁平几何上跑完，最后再做一次「结构化渲染」**。帧只影响层级，
不该牵动任何排版数值。代价是一次额外渲染。

## 7. 分区必须绑在**它要应用的**那份几何上

这是本轮最反直觉的一条。两次都错在同一个方向的两种极端：

- 第一次：冻在**校准后**、套在**校准前** → 59.37；
- 这一次：冻在**校准前**、套在**校准后** → 12 组只有 3 组建得成。

第二种错的机制很具体：`行 08` 组里 3 个表头文字（启动时间/状态/执行结果）在校准前
落在第 1 行、校准后被移到表头行。组的并集从 21px 撑到 63px，把表头一起圈进去。

现在的口径：**校准跑完 → 计算指纹 → 与分区声明的 `designSha256` 比对 → 再插入**。
不一致直接 `blocked-environment`，不静默错位。

## 8. 禁改项（新增五条）

| 禁改项 | 原因 |
|---|---|
| **分区文件必须带 `designSha256`** | 不带就等于允许跨版本静默错位（95.60 → 59.37） |
| **分区必须绑在「它要应用的那份几何」上** | 冻校准前、套校准后 → 12 组只剩 3 组 |
| **不要把分区容器插在校准之前** | 帧内文本坐标是相对父帧的，校准回路会被带飞（native 30 → 23） |
| **不要拿相对父帧的 `bounds` 当页面坐标** | 会让 `textBox` 写回局部值，标签整体飞出按钮 |
| **透明容器的深度不能固定成 0** | Frame 排到祖先之前，祖先被当成外人 |

## 9. 复现

```bash
PY="C:/Users/lzq/.conda/envs/omni/python.exe"
# 1) 先跑一次不带分区的基线，拿到校准后的几何
$PY scripts/image_figma_mvp.py --image <ref> --truth <truth> --out output/_base \
    --acceptance-policy 2.1 --reuse-prepared
# 2) 在这份几何上冻结分区（绑定的就是它要应用的几何）
$PY scripts/vlm_partition_probe.py --family light-form --run-dir output/_base --refresh
# 3) 再跑一次；校准照旧，最后插帧再渲染一次
$PY scripts/image_figma_mvp.py --image <ref> --truth <truth> --out output/_part \
    --acceptance-policy 2.1 --reuse-prepared \
    --partition output/_structure_partition/light-form/partitions.json
```
