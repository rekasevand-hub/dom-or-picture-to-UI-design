## R2-Q01 DOM 版具体容器的 true flow 边界

**证据范围**

本节只使用 DOM 版（`1:2`）节点。以下几何均来自 `.fig` 只读解析；坐标为父容器局部坐标，单位与画布一致（该画板变换为 1:1）。

**已知事实**

- DOM 版外层 `1:2` 是 `VERTICAL`，11 个直接子项（6 个内容 Frame + 5 个空白间隔），内部 124 个 Frame 都是固定坐标。
- `1:211 新书与推荐`（1440×554）有三个直接子项：`1:284 栏目标题` 790×38 @ (125,18)、`1:243 新书目录` 790×496 @ (125,58)、`1:212 图书推荐` 380×554 @ (935,0)。左栏标题与内容没有共同父容器；右栏自带 `栏目名称` 文本（y≈19.44），其列表从 y=58 开始。左右间隔 20，页面左右边距 125。
- `1:243 新书目录`（790×496）是 5 列 × 2 行，共 10 个 `1:244 图书` 卡片，每张 142×237。列 x = 21、173、325、477、629（列距 10）；行 y = 21、258（行距 0，237 紧接）。四边留白约为 21 / 19 / 21 / 1（左/右/上/下）。子项顺序是“下行从右到左，再上行从右到左”，与视觉阅读顺序相反。
- `1:101 在线图书目录`（1190×733）出现同样现象：21 个 `图书位置` 为 7 列 × 3 行，x=36…1008（列距 10），y=21/258/495（行距 0）；子项顺序同样是下行从右到左。可作为“DOM 顺序 ≠ 视觉顺序”的第二个样本。
- `1:244 图书`（142×237）内部：`1:247 图书封面` 142×142 @ (0,0)；`1:246 书名` 128×44 @ (8,151.28)；`1:245 作者` 130×18 @ (8,202.96)。封面通栏，文字左缩进 8；标题与作者之间约 7.68，卡片底部余 16.04；标题高 44 对应 16px 字号 / 22px 行高的两行。
- `1:213 推荐排行`（380×496）有 12 个直接子项：首个“展开条目”没有独立容器，`排名`、`图书封面`、`书名`、`展开条目底线` 是并列子项（y≈14.94–144）；其后 7 个 `排行条目` 378×44，y=145…409（步长 44，间距 0）；`查看更多` 378×41 @ (1,454)。即“首个展开条目 + 7 个普通条目 + 查看更多”，共 8 个排行内容；首条目高约 144，普通条目高 44，`查看更多` 与最后一条之间约 1px。
- `1:312 古籍目录`（790×365）是 2×2：4 个 `古籍` 373×162 @ x=16/410、y=21/203；行距 20、列距 21；另有 `古籍行分隔` 788×1 @ y=182 和 `古籍列分隔` 1×363 @ x=394。行分隔与上行底边（y=183）重叠 1px；列分隔距左列右边 5、距右列左边 15，并不严格居中。

**为什么问**  
R1 给了 flow 准入条件，但没有落到具体节点。DOM 版的关键难点不是“有没有 Auto Layout”，而是：DOM 顺序与视觉顺序相反、标题与内容没有共同父容器、封面通栏与文字缩进混用、首个排行项没有容器、网格分隔线落在间隔内。只有把这些节点在 2.0 里怎么建说清楚，才能写 `layout_plan` 的白名单，而不是又做一次“全局猜”。

3. `1:243`：10 张卡片宽度应 `FILL` 均分还是 `FIXED 142`？列距 10、行距 0 是否直接写入 `itemSpacing`？四边留白 21/19/21/1 应原样保留、吸附到 20/20/20/0，还是记录为“测量值 + 规范化值”两套？

## R2-Q06 中文文本度量、行高与字体回退

**已知事实**

- DOM 版：166 个 Text，以 Noto Sans SC 为主（Regular 115、Bold 38），另有 13 个排名数字用 Arimo Italic；行高 18px×79、22px×37、38px×28、30px×9、20px×9 等；`textAutoResize=HEIGHT` 138 个，另 28 个未写该字段。
- URL 版：166 个 Text，Inter；行高 1.4 RAW×117、1.375 RAW×31、100%×14、1.5 RAW×4。
- 上传版：160 个 Text，Noto Sans SC；全部 1.4 RAW。
- V1 的 `text_wrap.py` 优先用 computed `lineHeight`，缺失时按 `1.4em` 估算。

**为什么问**  
R1 明确说“统一 140% 行高不是精确复刻”，但没有给中文文本的逐角色度量规则。2.0 需要区分“测到的行高”“推断的行高”“Figma 实际渲染的行高”，否则文本盒看起来对、基线或换行却错了。

**请导师回答**
